# PRD: NRP План-факт WB

## 1. Назначение

Контролировать выполнение плана по компании, менеджерам и ключевым срезам WB. INDEEPA имеет планы по SKU, бренду, кабинету и категории; Vella v1 должна закрыть рабочий план-факт без обязательной полной parity.

## 2. Роли

- Мария: ставит и контролирует планы.
- Максим: проверяет план по маржинальной прибыли.
- Менеджеры: видят свой факт, отклонение и прогноз.
- `settings_editor/finance_editor`: импортирует или редактирует план.

## 3. Пользовательские сценарии

- Открыть план-факт за месяц и увидеть факт, план, отклонение, % выполнения.
- Понять прогноз до конца месяца и минимум в день.
- Посмотреть разрез по менеджерам.
- Импортировать план через Excel или отредактировать вручную.
- Видеть audit изменения плана.
- Перейти из провала плана в проблемные SKU/рекламу/цены.

## 4. Данные

- год, месяц, период;
- уровень плана: company, manager, brand, category, SKU, account;
- метрика: маржинальная прибыль, выручка, заказы, продажи;
- план;
- факт;
- отклонение;
- % выполнения;
- прогноз;
- минимум в день;
- расходы;
- actor/audit.

## 5. Поля, фильтры и контролы

- период, по умолчанию текущий месяц;
- плановый уровень;
- метрика;
- кабинет;
- бренд;
- категория;
- менеджер;
- SKU;
- import Excel;
- edit draft;
- validate;
- save/approve;
- export.

## 6. Расчеты и бизнес-правила

- `факт` заменяет неясное `накоплено`.
- % выполнения = факт / план.
- прогноз = факт + средний темп до конца месяца или согласованная формула.
- минимум в день = остаток плана / оставшиеся дни.
- Если план не заполнен, показывать понятный empty state, а не нулевую матрицу.
- Редактирование планов идет через draft/validation/approval.
- Финансовый факт не final, пока P&L не final.

## 7. Состояния

| State | Поведение |
|---|---|
| `loading` | Skeleton |
| `empty_plan` | План не заполнен, CTA на импорт/редактирование |
| `empty_fact` | Нет факта за период |
| `finance_pending` | Факт preliminary |
| `validation_error` | Ошибки import/edit |
| `no_access` | Read-only или скрыть финансы |
| `partial_data` | Часть менеджеров/SKU не сматчена |

## 8. Опасные действия

- импорт большого плана;
- изменение планов после начала месяца;
- сохранение планов на уровне SKU/бренда/категории;
- изменение факта вручную;
- export финансовых планов без права.

## 9. Что уже есть в Vella

- менеджерские представления;

## 11. v1 replacement minimum

- company + manager plan-fact;
- маржинальная прибыль как ключевая метрика;
- факт/план/%/прогноз/минимум в день;
- Excel/manual plan input;
- audit изменения планов.

## 12. Production hardening

- brand/category level;
- inline editable matrix;
- historical plan versions;
- drill-down from deviation to SKU/actions.

## 13. P2 / change request

- full INDEEPA planning by SKU/brand/account/category;
- Excel import до 150k строк как parity;
- day-by-day pivot matrix со всеми горизонтальными scroll-таблицами.

## 14. Сложность

v1 manager/company: 4-7 рабочих дней. Full multi-level parity: 10-15 рабочих дней.
