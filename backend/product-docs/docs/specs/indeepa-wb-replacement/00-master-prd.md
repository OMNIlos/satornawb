# Master PRD: INDEEPA WB -> Vella replacement

Дата: 2026-05-19  
Статус: PRD для согласования с Филом и разработки  
Основа: `research/33-indeepa-wb-scope-for-fil-2026-05-18.html`, live-аудиты INDEEPA от 2026-05-18, `ТЗ/TZ-WB.md`.

## 1. Назначение

Vella должна заменить INDEEPA в рабочем WB-контуре Огней. Замена означает не копию интерфейса, а production-систему, которая помогает Марии, менеджерам и Максиму принимать решения по цене, марже, рекламе, плану и остаткам без ручной сборки в INDEEPA/Excel.

Live-аудит показал, что INDEEPA WB состоит из четырех слоев:

- репрайсер: товары, цены, стратегии, настройки, отправка цен;
- safety: price guards, anti-spike входных метрик, блокировки;
- governance: аккаунты, роли, права, audit;
- NRP: Unit P&L, план-факт, РнП/реклама, рейтинг товара.

## 2. Роли

| Роль | Зачем использует |
|---|---|
| Мария / ecom-руководитель | Управляет WB-ценами, стратегиями, отчетами, планом, проблемными SKU |
| Менеджеры ecom/рекламы | Работают со своими SKU, рекламой, комментариями, проблемными строками |
| Максим / финансы | Проверяет P&L, налоги, расходы, план-факт и достоверность финансовых отчетов |
| Администратор | Подключает WB-аккаунт, токены, права, следит за ошибками интеграций |
| Дмитрий / разработка | Реализует backend, адаптеры, очереди, хранилище, UI и UAT |
| Фил | Согласует scope, change requests и клиентские ожидания |

## 3. Scope tiers

### v1 replacement minimum

Входит:

- репрайсер WB на реальных данных: таблица SKU, drawer, расчет маржи, price draft, apply jobs;
- 17 глобальных параметров INDEEPA как typed settings model;
- typed strategies: `4599 baskets/orders`, `4600 revenue dynamics`, Vella-адаптация ночного режима;
- `4445 spp_turnover` только как `discovery_required` placeholder; реализация входит в v1 только если Мария подтвердит правила до фиксации v1 cut;
- price guards: P_min/P_max, per-update, per-day, promo/min_price;
- input guards: СПП, остатки, себестоимость, логистика, выкуп, промо;
- роли `viewer`, `settings_editor`, `price_sender`, `finance_viewer`, `admin`;
- audit trail для настроек, расчетов, отправок цен, импортов, unlock;
- NRP-lite: Unit P&L, менеджерский plan-fact, РнП funnel, прозрачный рейтинг SKU;
- Excel export/import там, где это нужно для цен, планов и финансовых данных;
- visible states для loading, empty, error, partial data, no access.

### Production hardening

Входит после минимального cut или параллельно, если не блокирует:

- source registry: источник, freshness, fallback, confidence для каждой метрики;
- retry/backoff и status polling по WB price apply;
- версии формул и стратегий;
- расширенные saved views и column presets;
- full virtualization для больших таблиц;
- dashboard мониторинга интеграций и ночных jobs;
- richer campaign detail, плановые матрицы, детальные расходы.

### Full INDEEPA parity

Не считать v1 по умолчанию:

- visual rule-builder как INDEEPA;
- полный catalog полей, операторов, формул и расписаний;
- dependency graph всех INDEEPA extensions;
- NRP BI parity по всем уровням и всем внутренним таблицам;
- Excel plan import до 150k строк как полноценный плановый модуль;
- полная детализация рекламных кампаний и all-time metrics;
- копирование `Indeepa.Index` как закрытого индекса.

### Change request / Out

Отдельное согласование:

- Ozon/cross-marketplace;
- competitor following;
- управление WB автоакциями через API;
- PDF/share reports, если клиент отдельно вернет;
- прямая 1С-интеграция;
- black-box копия INDEEPA scoring.

## 4. Сквозные пользовательские сценарии

1. Мария открывает репрайсер, видит SKU с ценой, маржой, корзинами, заказами, СПП, акциями и статусом источников.
2. Система считает price recommendations и объясняет причину: стратегия, входные данные, ограничения.
3. Менеджер редактирует цену вручную или импортирует изменения через Excel, видит preview, diff и блокировки.
4. Пользователь с правом `price_sender` подтверждает отправку цен в WB.
5. Если источник дернулся, auto-send блокируется, SKU получает понятный freeze/warning state.
6. Максим открывает Unit P&L и видит, какие расходы съедают маржу и какие данные еще preliminary.
7. Мария смотрит plan-fact, видит факт, план, отклонение, прогноз и ответственного менеджера.
8. Рекламная команда смотрит РнП: показы, клики, корзины, заказы, расходы, CPC/CPO/ACoO/TACoO.
9. Менеджер открывает рейтинг SKU и переходит к действиям: поднять цену, проверить рекламу, ликвидировать, не трогать.

## 5. Сквозные данные

Обязательные домены данных:

- WB account и token health;
- SKU, nmId, vendorCode, внутренний артикул, бренд, категория, менеджер;
- цены до/после СПП, СПП, min_price, P_min/P_max;
- COGS, логистика, хранение, комиссия, налоги, операционные расходы;
- корзины, заказы, продажи, выручка, остатки, выкуп;
- акции и valid promo price;
- реклама: кампании, статусы, показы, клики, расходы, корзины, заказы;
- планы: год, месяц, уровень плана, метрика, факт, отклонение;
- роли, permissions, audit events;
- imports/exports, report runs, freshness/confidence.

## 6. Сквозные состояния

| State | Поведение |
|---|---|
| `loading` | Показывать skeleton и источник, который загружается |
| `empty` | Объяснить: нет данных за период, нет плана, нет кампаний, нет SKU |
| `error` | Показать scope ошибки, retry и last successful data |
| `partial_data` | Не скрывать экран; пометить поля preliminary/unknown |
| `no_access` | Показать, какого права не хватает, без утечки финансовых данных |
| `source_stale` | Запретить auto-apply, если stale-метрика критична для стратегии |
| `approval_required` | Дать diff и причину, почему нужен approval |
| `blocked_by_guard` | Заблокировать действие и показать конкретный guard |

## 7. Опасные действия

Все опасные действия идут через `draft -> diff/preview -> approval -> commit`:

- отправка цен в WB;
- изменение глобальных настроек репрайсера;
- изменение стратегии или расписания;
- массовый Excel import;
- разблокировка anti-spike freeze;
- изменение ролей и токенов;
- применение цены ниже P_min в ликвидации.

## 8. Что уже есть в Vella

- сильная рабочая оболочка Vella;
- таблицы, drawer, saved views, preview, audit-концепция;
- понятная связка репрайсера и отчетов;
- продуктовая логика вокруг действий, а не просто BI-таблиц;
- базовые PRD по репрайсеру и отчетам.

## 9. Что нужно доделать

- production backend price engine и WB adapters;
- persistence для настроек, стратегий, audit, saved views, comments;
- полная typed settings model для 17 параметров;
- source mapping и source registry;
- input anti-spike guards;
- roles/permissions на backend;
- NRP-lite на реальных данных;
- Excel import/export и большие таблицы;
- UAT на данных Марии/Максима.

## 10. Сложность

| Cut | Оценка |
|---|---:|
| v1 replacement minimum | 5-7 production-недель |
| strong v1 + hardening | 7-9 production-недель |
| full INDEEPA parity | 8-12+ production-недель |

Оценки зависят от WB API, стабильности СПП/рекламных данных, доступности финансовых отчетов и готовности Марии/Максима подтвердить формулы.

## 11. Главные scope-risk

- Клиент может услышать "замена INDEEPA" как "полная копия INDEEPA". Это неверно для v1.
- NRP оказался BI-модулем, а не одним отчетом.
- Rule-engine INDEEPA шире текущего ТЗ и должен остаться P2/change request.
- Реклама per-SKU/per-period может оказаться нестабильной и потребовать Excel/API fallback.
- P&L без подтверждения налогов, хранения и общих расходов нельзя выдавать как финальную финансовую правду.
- Стратегии 4442 и 4445 видны, но их правила не подтверждены в live-аудите. До подтверждения нельзя оценивать их как готовые v1-правила.

## 12. Что согласовать с Филом

- Формулировку для клиента: `Vella v1 заменяет критичный WB-контур, но не обещает full INDEEPA parity`.
- Считать ли 17 настроек репрайсера обязательными для v1. Рекомендация: да.
- Считать ли multi-level plan-fact по SKU/бренду/кабинету/категории v1 или P2. Рекомендация: manager/company v1, full matrix P2.
- Нужна ли campaign detail parity в v1. Рекомендация: базовый РнП v1, detail P2.
- Кто утверждает P&L-формулы: Максим обязателен.
- Нужно ли повторно идти к Марии по 4442/4445 и источникам СПП/рекламы. Рекомендация: да, до разработки этих стратегий.
