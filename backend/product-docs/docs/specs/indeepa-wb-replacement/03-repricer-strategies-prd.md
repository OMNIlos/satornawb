# PRD: Стратегии репрайсера

## 1. Назначение

Собрать v1-стратегии репрайсера как typed, тестируемые правила Vella. Не строить полный INDEEPA rule-engine в v1.

## 2. Роли

- Мария: выбирает и согласует стратегии.
- Менеджер: видит причину рекомендации.
- `settings_editor`: меняет параметры стратегии.
- `price_sender`: отправляет рассчитанные drafts.
- Разработка: реализует deterministic engine и тесты.

## 3. Пользовательские сценарии

- Выбрать стратегию для SKU/группы.
- Запустить dry-run и увидеть, какие SKU изменятся.
- Открыть объяснение: входные метрики, правило, новая цена, guards.
- Изменить параметры стратегии и увидеть diff.
- Понять, почему стратегия не рассчитала цену.

## 4. Данные

- strategy id, name, type, status;
- scope: SKU, saved view, бренд, категория, account;
- formula version;
- schedule;
- input metrics;
- output price plane;
- rule result;
- blocked guards;
- audit.

## 5. Стратегии

### 4599: Динамика корзин и заказов

Входит в v1.

Правила:

| Сценарий | Действие |
|---|---:|
| корзины растут, заказы растут | +3% |
| корзины не растут, заказы растут | +1% |
| корзины растут, заказы не растут | -1% |
| корзины не растут, заказы не растут | -3% |

Ограничения:

- рост выше базового коридора не более 5%;
- valid promo price учитывается, но не заменяет Vella P_min/min_price;
- если остаток 0 или данных мало, цена не меняется.

### 4600: Поддержание динамики выручки

Входит в v1 после согласования default metric/period.

| Динамика | Действие |
|---|---:|
| <75% | -5% |
| 75-85% | -4% |
| 85-95% | -3% |
| 95-105% | 0% |
| 105-115% | +3% |
| 115-125% | +4% |
| >125% | +5% |

Важно по источникам: в INDEEPA live-аудите зафиксированы процентные шаги. В `ТЗ/TZ-WB.md` для похожей стратегии есть рублевый floor: например `-5% или -30 руб`, `+4% или +20 руб`. Перед реализацией нужно выбрать один режим:

- `indeepa_percent_only`: повторяет live INDEEPA-логику;
- `vella_percent_or_rub_floor`: сохраняет TZ-логику `процент или рубли, что больше`.

До выбора режима dry-run должен показывать оба результата на примерах SKU, но production auto-send использует только утвержденный режим.

Дополнительно: если скорость заказов за 7 дней равна 0, снижать на 3% в день, пока guards разрешают.

### 4442: Ночной рост цен

Входит как Vella-адаптация, но не blind copy.

Из INDEEPA зафиксировано окно `01:00-05:00` и второй formula schedule `Всегда`; правила не подтвердились в snapshot. В `ТЗ/TZ-WB.md` окно повышения перед акциями зафиксировано как `23:00-06:00 МСК`, off-by-default.

v1-решение: сделать `night_price_mode` выключенным по умолчанию, с явным schedule, audit и вопросом Марии по окну.

### 4445: СПП + оборачиваемость

Не включать в расчет до уточнения правил.

В v1 можно заложить только тип `spp_turnover` со статусом `disabled/discovery_required`, чтобы UI и source registry понимали, что такая стратегия существует в INDEEPA. Реализация начинается только после подтверждения:

- какие пороги СПП;
- как считать оборачиваемость;
- какие шаги цены;
- какие upper/lower bounds.

## 6. Formula/rule layer

v1:

- typed strategies;
- фиксированные поля;
- фиксированные операторы внутри кода;
- тесты на каждое правило;
- версионирование формул;
- dry-run preview.

Не v1:

- пользовательский visual rule-builder;
- произвольные выражения;
- огромный dropdown полей;
- пользовательские schedule formulas как INDEEPA.

## 7. Состояния

| State | Поведение |
|---|---|
| `ready` | Можно считать и создавать draft |
| `disabled` | Стратегия отключена |
| `discovery_required` | Не хватает подтвержденных правил |
| `not_enough_data` | Не хватает периода/метрик |
| `source_stale` | Источник устарел |
| `guard_blocked` | Цена рассчитана, но заблокирована |
| `approval_required` | Результат требует подтверждения |

## 8. Опасные действия

- включение стратегии на большой группе SKU;
- изменение schedule;
- изменение percent steps;
- включение ночного режима;
- включение 4445 без подтвержденных правил.

## 9. Что уже есть в Vella

- концепт стратегий;
- reason/explanation в интерфейсе;
- preview/draft-first подход;
- базовые типы в PRD.

## 10. Что нужно доделать

- deterministic strategy engine;
- formula versions;
- test fixtures;
- dry-run;
- schedule runner;
- source dependency declaration;
- audit per calculation.

## 11. v1 replacement minimum

- `baskets_orders_4599`;
- `revenue_dynamics_4600`;
- `night_price_mode` off-by-default;
- `spp_turnover` только как disabled placeholder до уточнения; не считать реализованной v1-стратегией;
- strategy dry-run и explanation;
- no custom rule-builder.

## 12. Production hardening

- strategy simulation на исторических данных;
- per-scope rollout;
- версионированное сравнение результатов;
- alerts при аномальном количестве changes.

## 13. P2 / change request

- full INDEEPA rule-engine;
- custom formulas;
- field catalog;
- user-authored strategies;
- strategy marketplace/presets beyond Maria.

## 14. Сложность

Typed v1: 8-13 рабочих дней. Full rule-engine: 10-20+ рабочих дней отдельно.

- Для 4600 режим шага: percent-only как INDEEPA или percent/rub floor как `ТЗ/TZ-WB.md`?
- Какой period compare использовать?
- Ночной режим: `01:00-05:00` как в INDEEPA или `23:00-06:00 МСК` как в ТЗ?
- Используются ли 4442 и 4445 реально у Марии?
- На каком уровне назначаются стратегии в v1?
