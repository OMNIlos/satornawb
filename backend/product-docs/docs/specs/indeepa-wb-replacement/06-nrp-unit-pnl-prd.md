# PRD: NRP Unit WB / P&L

## 1. Назначение

Дать финансовую картину SKU: что реально зарабатывает товар после комиссии, логистики, хранения, себестоимости, налогов, рекламы и дополнительных расходов.

## 2. Роли

- Максим: владелец финансовой методологии.
- Мария: использует P&L для решений по цене, рекламе, ассортименту.
- Менеджер: видит ограниченный P&L по своим SKU.
- `finance_viewer`: доступ к финансовым деталям.

## 3. Пользовательские сценарии

- Открыть P&L по SKU/бренду/категории/менеджеру за период.
- Понять, что съедает маржу.
- Увидеть preliminary vs final financial data.
- Сравнить остатки FBS/FBO в штуках, себестоимости и цене реализации, если источник доступен.
- Перейти из P&L к SKU drawer и price decision.

## 4. Данные

- период;
- SKU/nmId/vendorCode/internal SKU;
- кабинет, бренд, категория, тег, strategy;
- выручка, продажи, заказы;
- COGS;
- комиссия WB;
- логистика;
- хранение;
- реклама;
- налоги;
- прочие расходы;
- нераспределенные расходы;
- маржа и маржинальность;
- FBO/FBS остатки в штуках;
- FBO/FBS остатки по себестоимости;
- FBO/FBS остатки по цене реализации;
- source type: operative/financial/final.

## 5. Фильтры и контролы

- период;
- кабинет;
- бренд;
- категория;
- внутренний тег;
- SKU/артикул МП;
- strategy;
- rating group;
- учитывать/не учитывать нераспределенные расходы;
- source confidence;
- export.

## 6. Расчеты и бизнес-правила

- P&L final строится только на подтвержденных финансовых отчетах WB или утвержденном fallback.
- До закрытия периода показывать статус `preliminary`.
- Нераспределенные расходы можно не распределять или распределять по согласованному правилу: выручка, заказы, остатки.
- Налоги и хранение требуют подтверждения Максима.
- Рекламные расходы не распределять на SKU, если источник только `campaign_only`.
- P&L должен объяснять компоненты, а не только итоговую маржу.

## 7. Состояния

| State | Поведение |
|---|---|
| `loading` | Загружаются финансовые блоки |
| `empty` | Нет продаж/данных за период |
| `finance_pending` | Финансовый отчет WB не закрыт |
| `tax_unconfirmed` | Налоговая формула не подтверждена |
| `partial_expenses` | Часть расходов не распределена |
| `no_access` | Финансовые поля скрыты |
| `mapping_missing` | Нет source mapping для метрики |

## 8. Опасные действия

- изменение COGS;
- импорт операционных расходов;
- изменение правила распределения расходов;
- пометка preliminary data как final;
- export финансовых данных пользователем без права.

## 9. Что уже есть в Vella

- P&L и маржа есть в текущей логике/PRD;
- связка с репрайсером и отчетами;
- финансовые pending states уже описаны.

## 10. Что нужно доделать

- normalized P&L model;
- source mapping;
- import/manual expenses;
- FBS/FBO stock valuation с fallback state для пустого или нерелевантного FBO;
- finance permissions;
- drill-down to SKU drawer.

## 11. v1 replacement minimum

- P&L по SKU/бренду/категории;
- preliminary/final state;
- основные расходы;
- FBS/FBO остатки как отдельные поля и состояния; если для Огней FBO пустой или нерелевантный, это не блокирует v1 P&L;
- ручной/Excel ввод операционных расходов;
- no-access для финансов.

## 12. Production hardening

- правила распределения расходов;
- сверка с weekly WB financial report;
- variance report;
- audit formula versions;
- richer waterfall `что съедает маржу`.

## 13. P2 / change request

- full NRP Unit WB BI parity;
- кросс-PL;
- автоматическая 1С-интеграция;
- все внутренние scroll/pivot таблицы INDEEPA.

## 14. Сложность

Оценка: 7-12 рабочих дней для production P&L v1 при доступных источниках. Блокер: подтверждение формул Максимом.
