# Вопросы по данным WB для передачи в разработку

Дата: 2026-05-25
Цель: подтвердить недостающие данные и правила расчета для WB-модуля Vella перед backend-разработкой.

## Сообщение для отправки

Коллеги, чтобы backend-разработчик корректно собрал WB-модуль, нам нужно подтвердить источники данных и несколько формул. Просьба ответить по пунктам и приложить примеры выгрузок/скринов, где они есть.

Если удобнее, можно разделить на два коротких созвона: отдельно с Марией по репрайсеру/отчетам и отдельно с Максимом по финансам/правам.

## 1. Вопросы к Марии

### Репрайсер и стратегии

1. На каком уровне применяются стратегии: SKU, группа SKU, категория, бренд или глобально?
2. Для стратегии 4600 какую логику используем: только процентное изменение или процент + минимальный рублевый порог?
3. Используются ли сейчас стратегии INDEEPA 4442/4445? Если да, какие у них правила?
4. Для ночного режима подтверждаем окно `23:00-06:00 МСК` или нужно другое?
5. Какие источники/поля должны блокировать отправку цены, если данные устарели или неполные?

### СПП и цены

1. Где сейчас надежнее всего смотреть СПП по конкретному SKU?
2. Если API не отдаст СПП, какой fallback допустим: ручной ввод, последний известный СПП, Excel-выгрузка или блокировка отправки цен?
3. В какой ценовой плоскости менеджерам удобнее задавать P_min/P_max: до СПП или после СПП?
4. Можно ли отправлять price draft вручную, если СПП неизвестен, но цена не отправляется в WB до проверки?

### Остатки, КТР и локализация

1. Откуда брать локальные заказы для индекса локализации: какой отчет, поле, склад/кластер?
2. Формулу локализации подтверждаем как `локальные заказы / все заказы * 100%`?
3. Таблица КТР по диапазонам локализации финальная или нужна новая версия?
4. Для доступного остатка подтверждаем правило: `остаток WB + от клиента`, а `к клиенту` не прибавляем?
5. Как считать решение по складу `норма/держать/дозагрузить`: какие поля и пороги используются?

### Реклама и РНП

1. Где сейчас берутся рекламные расходы по SKU за период?
2. Есть ли выгрузка/отчет, где видны SKU или nmId внутри рекламной кампании?
3. Если кампания не привязана к SKU точно, можно ли показывать ее только на уровне кампании без распределения расхода в P&L SKU?
4. Как считать ROI?
5. Как считать ДРР: от заказов, от продаж или оба варианта?
6. Для ATCR какой знаменатель использовать: переходы/просмотры карточки или клики?
7. Порог рекомендации на проверку рекламы подтверждаем: 21+ дней, ДРР >= 25%, расход >= 1500 руб, без OOS/новинки/акции/ликвидации?
8. Нужно ли исключать самовыкупы из рекламных рекомендаций?

### ABC, статусы и ликвидация

1. ABC-пороги подтверждаем: A = топ 20%, B = следующие 30%, C = нижние 50%?
2. Вторая буква ABC считается по чистой прибыли после всех расходов?
3. Какие статусы товаров нужны в первой версии: локомотив, новинка, средний, слабый, убыточный, неликвид, ликвидация?
4. Какие пороги использовать для каждого статуса?
5. По каким критериям товар попадает в кандидаты на ликвидацию?
6. Критерии ликвидации должны выполняться все вместе или достаточно одного/нескольких?
7. Когда разрешено уходить в отрицательную маржу при ликвидации?

## 2. Вопросы к Максиму

### P&L, хранение и расходы

1. Какие финансовые показатели должны быть в первой версии P&L?
2. Нужно ли считать налоги/НДС в первой версии?
3. Какая налоговая база: выручка покупателя до комиссии/логистики или другой показатель?
4. Какой налоговый процент и есть ли пороги по обороту?
5. Как распределять хранение WB, если оно приходит общей суммой?
6. Как распределять общие расходы: по SKU, категории, менеджеру, периоду или вводить только общей строкой?
7. Какие расходы вводим вручную/Excel в первой версии?

### Финансовые права

1. Кто видит P&L полностью?
2. Какие финансовые поля могут видеть менеджеры?
3. Кто может экспортировать финансовые отчеты?
4. Кто может подтверждать отправку цен в WB?
5. Кто может подтверждать отрицательную маржу при ликвидации?

## 3. Что нужно приложить

- пример выгрузки/скрина по СПП на SKU;
- пример рекламного отчета с расходами по SKU или кампаниям;

- пример P&L/финансового отчета WB;

## 4. Внутренний backend discovery checklist

Этот раздел не отправлять клиенту как вопросник, он для команды разработки:

- подтвердить WB endpoints/exports для всех отчетов;
- подтвердить WB Ads fields и rate limits;
- подтвердить price apply endpoint, polling, task size, row-level errors and retry/backoff;
- подтвердить source freshness для каждого sync job;
- проверить, какие empty periods возвращают `204`, а какие пустые массивы;
- подтвердить, какие raw payload refs можно хранить sanitized для диагностики.
