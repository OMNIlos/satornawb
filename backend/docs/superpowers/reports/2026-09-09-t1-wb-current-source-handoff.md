## Lifecycle, page graph and exact bytes

Run fields `state TEXT`, `version INTEGER`, trusted `started_at TIMESTAMPTZ`, nullable
DB `finished_at TIMESTAMPTZ`, NULL-only `source_observed_at TIMESTAMPTZ`, nullable
`received_at TIMESTAMPTZ`, nullable `manifest_checksum TEXT`, BIGINT
`page_count/raw_row_count/fact_count`, nullable safe `safe_error_code TEXT`:

- Creation is collecting/version0, zero provisional counts, NULL terminal fields.
  Omit run_id/ingest_sequence. BEFORE INSERT rejects explicit non-NULL values and
  assigns UUIDv4/nextval, with no masking defaults. Supply actual trusted collection
  started_at (not in the future); it remains immutable and is not provider time.
- Append complete accepted page+typed facts in a transaction while collecting.
  Deferred checks enforce every page's typed raw-row count, contiguous page_no
  and offsets, common limit, nondecreasing accepted receipt time, no page after a
  short page, and known size count = source_size_count-unresolved_size_count.
  Receipt time is bounded UTC year 1..9999 and between trusted run start and DB finalization.
  Every `source_observed_at` remains NULL. No raw page JSON column exists.
- Finalize once with expected state collecting/version0 and new terminal/version1.
  Supply exact counts, received_at, manifest and safe error; omit finished_at,
  which the DB assigns. Collecting counters remain zero until that transition;
  inspect stored pages when interim accepted-prefix counts are needed.
- Failed has zero pages/raw rows/facts and NULL receipt/manifest. Invalid first
  page becomes failed. Partial has positive accepted pages and non-NULL last
  receipt/manifest plus safe error. Complete has positive pages, explicit short
  terminal (including explicit empty), exact counts and no safe error.
- Product count is raw goods count; fact count is products plus stored known
  sizes. Complete additionally requires every product source_size_count>0 and
  unresolved_size_count=0. Unresolved product identity metadata forces a partial
  terminal to use SOURCE_IDENTITY_UNRESOLVED. Empty goods may complete. Existing
  `GoodsPriceRun.complete` continues to describe transport completion only.
- Stock raw/fact counts are equal; strict duplicate identities are rejected by
  the native grain, including NULL chrt_id. Equal duplicate payloads do not collapse.

Only price `wb_goods_prices_v1` / `wb-goods-prices/v1` and stock `wb_warehouse_v1`
/ `wb-warehouse-stocks/v1` are accepted. Request bytes are compared byte-for-byte
to the closed existing CollectionRequest envelope: POST, empty query, price

## Atomic publication, replay and audit

Use READ COMMITTED. Caller-owned live source/origin/permission guard precedes the
DB statement account lock; account/credential binding precedes run then head/domain
work. Statement triggers lock the exact GUC WB account before tuple mutation.
The trusted service must acquire its complete guard/credential locks before
run/head operations and keep them until root commit. SQL role/worker enum is not
a principal and supplies no worker permission bootstrap.

The repository creates a run with INSERT RETURNING run_id/ingest_sequence; request
replay first finds owner/source/request_key and compares all immutable intent.
One family sequence orders admitted requests, not provider business timestamps.
Runtime cannot INSERT/UPDATE ingest_sequence or call setval successfully. USAGE
allows burning nextval but not choosing stored ordering; a caller-supplied non-NULL
sequence is rejected even if it equals the next value.

For finalize_and_publish, append pending facts, finalize collecting0→complete1,
then INSERT head version1 if absent, or UPDATE head with exact expected version
and new version=old+1, run_id and published_sequence. First absence is an INSERT
condition, not an upsert that overwrites a competitor. Inspect rowcount; CAS loss
must raise through the ROOT transaction, rolling back facts/run/audit/head. Do not
catch a CAS failure in a savepoint and commit an unintended terminal.

Head guards require a complete exact-context run, its exact sequence, strictly
newer sequence for replacement, unchanged owner/context, and finalization in the
same transaction (`xmin` matched to current top-level transaction). Use top-level
root finalization/publication, not nested savepoint finalization. A separately
finalized `finalize_without_publish` run is immutable history and cannot later be
published by issuing another CAS. This keeps sealed replay from changing the head.
Old run finishing late cannot replace a newer published sequence; service may
separately seal it without publishing after losing/declining publication.

Page/fact INSERT is append-only, never ON CONFLICT DO UPDATE. While collecting,
the page insertion guard suppresses an exactly identical page and raises
wb_current_page_conflict for changed intent at either page-number or offset slot,
including callers using ON CONFLICT DO NOTHING. Whole-page service replay
must first compare the entire persisted intent (including bytes' checksum,
offset/limit/time/status/count/terminal/request_id and typed facts); only exact
intent is a no-write replay. Changed page slot conflicts. Sealed run replay
compares all final metadata/counts/manifest and returns history without INSERT,
audit or another head CAS. An exactly unchanged run/head UPDATE is suppressed,
but this is not a substitute for full service replay comparison.

Audits are automatically inserted by run/head AFTER triggers, not manually
authored by the repository. Only run.created, run.completed, run.partial,
run.failed and current.published exist. Typed composite snapshots capture the
complete before/after run and head, including versions/counts/binding; worker/NULL
actor and UUID/timestamp are database-controlled. Audit column INSERT grants
support these SECURITY INVOKER triggers; direct INSERT fails trigger-depth guard.
No caller audit ID/timestamp, history UPDATE/DELETE or TRUNCATE is allowed.

Every family relation schedules deferred graph validation. It requires reciprocal
creation and terminal witnesses (one or two exact run events), exact immutable
before/after snapshots, contiguous head event versions and matching predecessors,
strict sequence growth, and an actual current head equal to the last publication
event. It rejects ghost audits, orphan heads and unwitnessed terminal/head changes.
Switching either owner GUC cannot hide earlier pending writes: captured owner
must still match at deferred check time or the transaction fails.

Latest attempt and last complete are separate queries: the run index orders exact
context by ingest_sequence DESC; head points only to a complete publication. No
TTL default or stale→fresh fallback exists. Source freshness/apply policy is a
required owner decision; schema does not invent it or provider atomicity.
