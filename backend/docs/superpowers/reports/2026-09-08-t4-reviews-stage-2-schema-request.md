## Common types and ownership

Every new relation carries non-null organization_id INTEGER, marketplace_account_id INTEGER and marketplace VARCHAR(16), checked to wb|avito. IDs are internal UUIDs except run_sequence/revision/version BIGINT. Timestamps are TIMESTAMPTZ. No user/default organization or account fallback.

Every relation has a composite FK (organization_id, marketplace_account_id, marketplace) to marketplace_accounts(organization_id, marketplace_account_id, marketplace), ON DELETE RESTRICT. This existing target uniqueness is already present.

Internal references below must include organization, account and provider; an internal UUID alone is not an ownership proof. Add the exact composite unique keys needed as FK targets. All FK deletes are RESTRICT, never cascading customer facts away when an account is disconnected.

External review IDs use nonempty TEXT and are preserved byte-for-byte after canonical normalization; do not coerce opaque/leading-zero identifiers into integers. content_checksum uses VARCHAR(64), checked as lowercase SHA-256 hex. Source-schema/normalization versions are nonempty TEXT, not an invented DB enum.

## 1. review_sync_runs_v2

Fields:

- sync_run_id UUID primary key.
- Common owner columns above.
- source_run_id TEXT NOT NULL CHECK nonempty: supplied by the account-owned ingestion invocation.
- run_sequence BIGINT GENERATED BY DEFAULT AS IDENTITY, positive and UNIQUE; server-issued ordering token, never client-selected in runtime.
- request_checksum VARCHAR(64) NOT NULL: digest of the typed account/provider/source-window/stream invocation, excluding credentials, raw payload and delivery timestamps.
- status VARCHAR(16) NOT NULL CHECK running|complete|partial|failed.
- completeness VARCHAR(16) NOT NULL CHECK complete|partial. A running/failed run cannot claim complete coverage.
- started_at TIMESTAMPTZ NOT NULL; completed_at nullable. Terminal status requires completed_at; running requires null.
- observed_count BIGINT NOT NULL DEFAULT 0 CHECK >= 0.
- manifest_checksum VARCHAR(64) NULL: non-null for complete/partial terminal states; null allowed while running or failed.
- coverage JSONB NOT NULL: typed evidence only: from/to nullable UTC timestamps, streams of {name, terminalReached}, pagesObserved nonnegative integer, providerEndReached boolean. No raw cursor URLs, headers, bodies, customer text or secrets. Application validates exact keys/types and rejects unknown fields.
- error_code VARCHAR(64) NULL: safe allowlisted code, no raw exception text.

Constraints/indexes:

- UNIQUE (organization_id, marketplace_account_id, marketplace, source_run_id).
- UNIQUE (organization_id, marketplace_account_id, marketplace, sync_run_id).
- UNIQUE (organization_id, marketplace_account_id, marketplace, sync_run_id, run_sequence) for a scoped ordering reference.
- Index (organization_id, marketplace_account_id, marketplace, started_at DESC, sync_run_id).
- Row version or expected-state predicate for finalization; final run status/manifest is immutable after completion. Same source_run_id + same request_checksum returns the recorded run. Same key + another request returns a conflict, not another run.

The sequence is reserved before the existing provider fetch when shadow is enabled, and the one fetched DTO is shared with the shadow normalizer. No additional provider call. A legacy DTO without an explicit verified account/run binding cannot be guessed into this store.

## 2. review_facts

This is a current identity/pointer, not another copy of review text.

Fields:

- review_id UUID primary key; common owner columns.
- external_review_id TEXT NOT NULL CHECK nonempty.
- current_observation_id UUID NULL only during initial insertion in the transaction.
- version BIGINT NOT NULL DEFAULT 0 CHECK >= 0: optimistic-concurrency version.
- last_source_run_id UUID NULL and last_source_run_sequence BIGINT NULL, paired; references the scoped run key.
- source_order_state VARCHAR(16) NOT NULL CHECK current|ambiguous; ambiguous_observation_id UUID NULL, composite owner/review/observation FK. The ambiguity marker is paired with that ID and blocks draft approval/send even when the current pointer remains on the previous observation.
- first_observed_at and last_observed_at TIMESTAMPTZ NOT NULL.

Constraints/indexes:

- UNIQUE (organization_id, marketplace_account_id, marketplace, external_review_id).
- UNIQUE (organization_id, marketplace_account_id, marketplace, review_id).
- Composite FK (owner columns, review_id, current_observation_id) to observation owner/review/ID below. The nullable creation pointer avoids inventing placeholder observations.
- Committed usable facts must have current_observation_id and version > 0. Enforce via deferred constraint trigger or an equivalent T1-approved transactional invariant; do not permit a committed half-created identity.
- Index (organization_id, marketplace_account_id, marketplace, last_observed_at DESC, review_id).

Do not add CatalogSku ownership here. Resolve product by exact (organization, account, external_product_id) through existing marketplace_products. Resolve Offer/CatalogSku only with unambiguous existing catalog mapping.

## 3. review_observations

Immutable normalized evidence. Fields:

- observation_id UUID primary key; common owner columns.
- review_id UUID NOT NULL; composite FK to review_facts owner/review key.
- revision BIGINT NOT NULL CHECK > 0; monotonically increasing per review.
- source_run_id UUID NOT NULL; composite FK to review_sync_runs_v2 owner/run key.
- external_product_id TEXT NULL: exact normalized WB nmId / Avito itemId, not CatalogSku.
- source_created_at TIMESTAMPTZ NOT NULL; source_updated_at TIMESTAMPTZ NULL.
- rating SMALLINT NULL CHECK rating BETWEEN 1 AND 5.
- text TEXT NULL: customer text, restricted domain storage only, never generic audit.
- answered BOOLEAN NOT NULL; can_answer BOOLEAN NULL (unknown is not true).
- source_status TEXT NULL; preserve provider-native status, no merged WB/Avito state machine.
- observed_at TIMESTAMPTZ NOT NULL.
- source_schema_version TEXT NOT NULL; normalization_version TEXT NOT NULL.
- content_checksum VARCHAR(64) NOT NULL with lowercase SHA-256 check.

Constraints/indexes:

- UNIQUE (owner columns, review_id, revision).
- UNIQUE (owner columns, review_id, observation_id), target for current pointer and run items.
- Composite owner/review and owner/run FKs as above.
- Index (owner columns, review_id, revision DESC).
- Runtime role has SELECT/INSERT only, not UPDATE/DELETE. Any stronger trigger protection must preserve migration-role ownership and safe restore procedures.

Do NOT make (review_id, content_checksum) globally unique. A → B → A in newer source observations is a new revision, whereas an exact replay of the same run or unchanged current source is deduplicated. Global checksum uniqueness would erase that distinction.

Existing normalizer does not retain provider answer ID/body. Stage 2 must not fabricate them or authorize send from answered=false alone; verified answer evidence for ambiguous recovery is a separate Stage 4 prerequisite.

## 4. review_sync_run_items

Immutable evidence linking a run to the exact observation without duplicating customer text.

Fields:

- Common owner columns.
- sync_run_id UUID NOT NULL; review_id UUID NOT NULL; observation_id UUID NOT NULL.
- content_checksum VARCHAR(64) NOT NULL.
- ordinal BIGINT NOT NULL CHECK >= 0; stable normalized order within the accepted run.
- observed_at TIMESTAMPTZ NOT NULL.

Constraints/indexes:

- Primary key (organization_id, marketplace_account_id, marketplace, sync_run_id, review_id).
- UNIQUE (owner columns, sync_run_id, ordinal).
- Composite FK owner/run; composite FK owner/review/observation.
- Observation reference must agree with content_checksum, via an additional composite target unique/FK or explicit constraint trigger; no cross-observation checksum substitution.
- Index (owner columns, review_id, sync_run_id).
- Runtime role SELECT/INSERT only, not UPDATE/DELETE.

## Transaction and concurrency acceptance rules

T4 implements these after the schema is accepted:

1. Establish tenant context and validate current active membership, effective reviews permission, selected account scope, canonical provider and account binding. Workers revalidate the recorded authorized scope before commit; credentials are resolved only at the provider adapter boundary.
2. Reserve a run using a DB-generated sequence before fetch; never hold a DB transaction open during provider I/O. Final ingestion is one transaction over already obtained DTOs.
3. Revalidate and lock the exact account, then lock review identities in deterministic order. Account locking serializes this bounded write path; expected version protects stale callers. No JSON/global-memory fallback on DB error.
4. Validate source_run_id/request checksum and normalize with existing canonical_contract.py. For a finalized run, exact replay requires the entire manifest, count, completeness and coverage to match, not merely the overlap of individual items. The manifest is SHA-256 of canonical sorted-key UTF-8 JSON containing the sorted array of (external_review_id, content_checksum), normalized typed coverage and completeness; reject duplicates before hashing. A missing/extra/changed item or coverage change is a conflict and must not mutate the original terminal run. For an unfinished run, a conflicting duplicate for the same run/review fails that ingestion transaction, records only a safe failure code separately if DB remains available, and does not silently select a winner.
5. Changed current source in an admissible newer run creates revision N+1 and advances the pointer with CAS. Unchanged current source reuses the observation and records a new run item. Both paths advance last_source_run_sequence/ID and version to the newest accepted run: these are ordering watermarks, not provenance of the current observation (which has its own source_run_id). Thus seq1=A → seq3=A → late seq2=B cannot regress A. Replaying an old run never resets the current pointer or watermark.
6. A known older provider source_updated_at cannot replace newer provider evidence. Otherwise the earlier server-issued run_sequence cannot overwrite a later run. Equal provider timestamps with differing content are ambiguous: insert immutable conflicting evidence, preserve the previous pointer, set source_order_state=ambiguous and ambiguous_observation_id, increment version and advance the watermark. Approval/send reads must reject the durable marker. Only a later admitted run with a strictly newer provider source_updated_at than both conflicting observations may automatically clear it; missing/equal timestamps or merely repeating old content cannot. Operator resolution is a separate future audited command, not part of this schema slice. Run ordering is not proof of provider freshness.
7. Finalize run status/count/manifest only after all accepted items commit. Partial/error runs never mark absent reviews answered/deleted. Even complete windowed coverage does not prove deletion outside that window; Stage 2 performs no absence-based tombstoning.
8. Account disconnect/provider binding change/revoked membership before commit aborts the canonical write. External account ID is rechecked against the original invocation binding under lock.
9. No current fact mutation occurs after a failed CAS; surface conflict and require a fresh read. No blind retry of business commands.

The run-item content checksum links immutable evidence; mutable ingestion operational status is not an approval record. No send capability is enabled by this schema.

## RLS, grants and migration gates for T1

- ENABLE and FORCE RLS on all four new relations, USING and WITH CHECK on organization_id = NULLIF(current_setting('app.organization_id', true), '')::integer, following existing platform migrations.
- Runtime role NOSUPERUSER/NOBYPASSRLS. No-context/wrong-organization SELECT/INSERT/UPDATE/DELETE probes on disposable PostgreSQL, not only SQLite.

- Add minimal runtime table/identity-sequence grants; no global grants. Immutable tables do not receive UPDATE/DELETE.
- Additive expand only. No legacy row rewrite, no default-on behavior, no production backfill, no triggers that mutate legacy tables.

- Downgrade must refuse to drop any nonempty canonical table unless a separately authorized archival/removal procedure has been completed. Empty disposable tables may be removed in FK-safe order. Do not cascade-drop or silently lose immutable evidence.

No guessed account based on count/title/latest token.

## Exact acceptance scenarios

- Same external review ID in two WB accounts, WB versus Avito, and two organizations produces separate identities.
- Same run + same request/facts is idempotent; same run key + changed request or conflicting fact is a conflict.
- Unchanged source in a new run reuses evidence; changed source creates N+1; A → B → A keeps three revisions.
- Earlier run finishes late and cannot replace newer current evidence; known older provider timestamp also cannot replace it.
- seq1=A → seq3=A (unchanged) → late seq2=B preserves A and watermark 3.
- Equal timestamp/different content sets durable ambiguity; restart keeps approval blocked; repeating old content does not clear it.
- Finalized-run replay with one added/missing item or changed coverage fails and preserves the original manifest and terminal status.
- One absent review in a partial response keeps its old state.
- Concurrent inserts/updates, CAS conflict, process restart and DB outage preserve committed facts without fallback.
- Cross-account FK, wrong/no tenant context and revoked membership are rejected.
- Unknown can_answer stays null, and normalized text/checksum are preserved exactly.
- Synthetic customer-text sentinel never appears in generic logs, audit, task args/results or safe errors.
- Count/manifest mismatch cannot finalize a complete run.
- Direct observation/run-item UPDATE/DELETE with runtime role is denied.
- Empty downgrade passes; nonempty downgrade is refused without data loss.
