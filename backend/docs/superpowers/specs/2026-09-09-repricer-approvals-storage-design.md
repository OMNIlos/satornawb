# T2 approvals: three-relation physical design

2026-09-09. T1 local architecture decision from the accepted T2 request. Design only: no migration allocated, runtime implementation, DB test or deployment claimed. Companion implementation follows the actual then-current sole head.

Authority: exact `45f94a39627ebe2916903e9e5e0930844f3daaf5:backend/docs/superpowers/reports/2026-09-09-t2-reserve-dispatch-contract-amendment.md`, including appended PostgreSQL text/UUID amendment; exact same-commit `app/modules/wb_repricing.py`, `wb_repricing_repository.py`, `wb_repricing_dispatch.py`. Prior `t2-prerequisite-review.md` supplies original gap disposition. Read committed T1 HEAD infra/db and migration ACL patterns only to check local integration conventions. No foreign worktree source.

## Decision

Implement exactly approvals, attempts and audit, with bounded surrogate UUID references, full exact text kept out of B-tree identity keys, NUMERIC integral business/version values, immutable canonical bytea and independent exact SQL reconstruction. Serialize each account's mutation commands in READ COMMITTED using the canonical account row. Enforce lifecycle/audit atomicity with **write-once audit witness FKs plus deferred validators**, not a best-effort audit insert or a hash-only logical identity.

No unresolved T2 domain decision blocks this design. The accepted text amendment rejects NUL/unpaired surrogates before hashing and preserves all valid Unicode. No lease/retry/outbox/context/settings/source schema is added. Real actor authorization, provider result proof, worker activation, retention and writer cutover remain separate service/owner gates.

## 1. Physical types and common helpers

- Existing owner/catalog/member FK IDs: canonical INTEGER, positive; account includes provider discriminator constant `marketplace='wb'` with composite account/provider FK. Keep user IDs out of this schema; membership is the canonical actor.
- Surrogate `approval_row_id UUID`, attempt ID UUID, `audit_event_id UUID`: generated by trusted application/DB UUID4 generation, never external approval ID. Check UUID lexical version/variant via `uuid::text` against exact lowercase UUID4 grammar; audit/approval surrogates are physical implementation IDs, attempt UUID preserves the domain contract. UUID surrogates avoid new identity sequences and long natural-key FKs; this slice therefore needs no new sequence USAGE/UPDATE grants.
- Business integral values (`nm_id`, recommended/optional minimum price, size_id) and approval/claim/audit versions: unconstrained `NUMERIC`, NOT NULL/positivity as appropriate, `value = trunc(value)` and explicit finite checks excluding NaN, Infinity and -Infinity. Do **not** use `NUMERIC(p,0)`, which can round input before CHECK, or int32/bigint business caps absent from the contract. Attempt versions are tiny finite state constants and can use SMALLINT.
- PostgreSQL still has finite storage limits; an extreme legacy Python integer beyond PostgreSQL NUMERIC capacity must fail a lossless-import preflight explicitly. Do not claim unlimited storage or truncate. Ordinary integers beyond BIGINT, including valid v1 values fitting 4096 request bytes, must round-trip exactly. SQL drivers return Decimal; the typed repository converts only after checked integral/finite validation.
- Exact free text (`approval_id`, article_id, upload ID): `TEXT COLLATE "C"`, no arbitrary length limit. SHA256/checksum/action/dispatch/lookup digests: TEXT or CHAR(64) with exact `[0-9a-f]{64}`; prefer TEXT to avoid blank-padding semantics. No dynamic-length business text in an index/FK target.
- TIMESTAMPTZ for all times, reject infinities; service supplies one trusted transaction clock value per command. created/updated and attempt timestamp relationships follow domain exactly. No caller-body timestamps. No default TTL/retention.

Provide small schema-qualified immutable helpers: `repricer_exact_text`, `repricer_integral_finite`, `repricer_safe_code`, `repricer_ascii_json_string`, `repricer_integer_decimal`, `repricer_request_bytes`, `repricer_action_key`, `repricer_dispatch_key`. Fixed signatures, no dynamic SQL. Trigger routines are VOLATILE, SECURITY INVOKER unless an independently justified narrow privilege is needed. Qualify referenced objects and constrain search_path; revoke PUBLIC execution on mutating/trigger helpers and restore only necessary runtime access. Helpers do not decrypt, connect or resolve a secret.

`repricer_exact_text` matches Python edge-whitespace semantics rather than `btrim(text)`'s ASCII-space-only default. Reject empty strings and any leading/trailing character Python considers whitespace: U+0009..000D, U+001C..0020, U+0085, U+00A0, U+1680, U+2000..200A, U+2028/U+2029, U+202F, U+205F, U+3000; ordinary interior characters remain exact. PostgreSQL UTF-8 text already cannot represent NUL/unpaired surrogates; application amendment rejects them before hashing/errors. Only **v1 article_id** additionally excludes interior U+0000..001F and U+007F, as dispatch.py:100–102 requires; do not impose that extra restriction on valid legacy article/approval/upload text.

Business/nullability CHECK mirrors kernel exactly:

- pending: no claimant/decider/reason/error/upload/result;
- applying: claimant required, others above NULL;
- rejected/blocked: decider+reason required, claimant/error/upload/result NULL;
- applied: claimant+upload required, decider/reason/error NULL; legacy result may be NULL, new v1 result must be required through outcome/attempt invariant;
- failed/ambiguous: claimant+safe_error required, decider/reason/upload/result NULL.

Legacy code grammar remains `[A-Za-z][A-Za-z0-9_]{0,127}` for all approval reason/error/result fields. Only new attempt failures/outcome audit use the eight-code allowlist. Legacy bytes and v1-only discount/size/min typed projections must be NULL; import preserves original checksum/action key/status/version/actors exactly after proven canonical identity. A v1 insert must be pending/version0, >=50 recommended price, exact request bytes, and only creation witness populated. New actionable intent cannot be inserted with legacy status semantics.

BEFORE ROW guard rejects changes to identity, owner, request_format, typed intent, bytes/hash/key or created_at; rejects all DELETE/TRUNCATE and updates to terminal/legacy rows. A permissible approval transition increments version exactly once and updates updated_at monotonically. Reserve/dispatch do not UPDATE approval business state/time/version; their audit belongs to the attempt. No physical cleanup path or unconditional UPDATE permission bypass is introduced.

## 3. Exact ASCII bytes, hashes and reconstruction

Reconstruct v1 request directly from validated typed SQL fields in this exact sorted-key order:

```text
{"accountId":INT,"approvalId":STR,"articleId":STR,"catalogSkuId":INT_OR_NULL,
 "discountPct":INT,"minPriceKopecks":INT_OR_NULL,"nmId":INT,
 "organizationId":INT,"priceKopecks":INT,"schema":"wb-price-apply/v1",
 "sizeId":INT_OR_NULL}
```

The displayed newline/spaces are explanatory only: emitted bytes have none. `repricer_integer_decimal` emits integral finite NUMERIC in plain decimal without exponent, decimal point, plus sign or leading zeros; NULL optional inputs emit literal null. This excludes alternate encodings like 1.0/1e0 even if SQL NUMERIC equality considers them equal.

`repricer_ascii_json_string` emits double-quoted JSON with Python `ensure_ascii=True` escaping: quote/backslash; short escapes for backspace/formfeed/newline/carriage-return/tab; lowercase four-hex `\u` for remaining code points below U+0020 or outside printable ASCII U+0020..007E; supplementary Unicode as exact lowercase UTF-16 surrogate-pair escapes. It preserves `/`, combining sequences and Unicode code points; no normalization. Input surrogates/NUL are rejected by domain/DB representation, not repaired.

Enforce bytea length1..4096, `canonical_request_bytes = repricer_request_bytes(typed fields)` and request_checksum=`encode(sha256(canonical_request_bytes),'hex')`. Use PostgreSQL built-in sha256(bytea), already compatible with modern local Postgres; do not add pgcrypto merely for hashing. Native `jsonb::text`/json_build_object output is **not** Python ASCII canonical JSON and cannot be accepted as a substitute. The equality check with direct reconstruction rejects non-ASCII raw encodings, alternate escapes/whitespace, key reordering, duplicate/unknown/missing fields, booleans/string numerics, omitted nulls and altered typed projections without relying on a JSON parser to retain lexical facts.

Action key for both formats is SHA256 of exact ASCII compact array `[org_number, account_decimal_STRING, approval_id_STRING, request_checksum_STRING]` (kernel.py:93–110). Account is a **string in this array**, unlike numeric accountId in request and numeric account in dispatch key. Preserve legacy key/checksum; compare to computed identity and reject mismatching import rather than rewriting it.

Dispatch key is SHA256 of exact ASCII compact array `["wb-price-dispatch/v1", org_number, account_number, approval_id_STRING, action_key_STRING, attempt_UUID_STRING]` (dispatch.py:155–163). Store/check immutable key even before marker. SQL bytes parity must be tested against exact 45f94a3 serializers, including Cyrillic, combining text, emoji, quote/backslash/control boundaries and numbers beyond BIGINT. No request/provider body goes into audit/logs/errors.

## 4. Attempts relation

`wb_repricer_price_apply_attempts` has attempt_id UUID4 PK; organization/account/approval_row_id scoped FK; unique(org,account,approval_row_id) enforces **zero or one lifetime attempt**; unique(org,account,attempt_id) and unique(org,account,dispatch_key). References use surrogate approval identity rather than indexing long approval text. Joins reconstruct domain scope exactly.

Immutable columns: action_key/checksum, claim_version positive integral NUMERIC, claimed_by_membership_id canonical INTEGER and org FK, reserved_at. State/version/time/outcome: status; version SMALLINT0..2; updated_at; nullable dispatch_at, finished_at, safe_error_code, wb_upload_id, result_code. Audit witness columns: reserved_audit_id UUID NOT NULL, dispatched_audit_id UUID NULL, outcome_audit_id UUID NULL; deferred scoped FK to audit. Append-only history semantics apply to marker/witnesses/identity, while this single attempt row's lifecycle is mutable.

| state | version | dispatch_at | finished_at | result fields |
|---|---:|---|---|---|
| reserved | 0 | NULL | NULL | all NULL; updated=reserved |
| dispatched | 1 | required | NULL | all NULL; updated=dispatch |
| applied | 2 | required | required | upload+result required, error NULL |
| failed pre-marker | 1 | NULL | required | eight-code error required, upload/result NULL |
| failed post-marker | 2 | required | required | error only WB_APPLY_REJECTED, upload/result NULL |
| ambiguous | 2 | required | required | eight-code error required, upload/result NULL |

Timestamps: reserved<=dispatch<=finished where present; terminal updated=finished, no backward time. Insert only reserved0; updates only reserved→dispatched/failed or dispatched→applied/failed/ambiguous; terminal immutable. Dispatch marker is write-once, no replacement reservation, no lease/renew/retry columns. Attempt state/error checks agree with 45f94a3:dispatch.py:210–246,309–328. A typed safe error cannot itself authenticate a provider rejection; trusted adapter still owns evidence.

## 5. Audit relation and write-once witness design

`wb_repricer_price_approval_audit`: audit_event_id UUID4 PK; org/account/approval_row_id scoped FK; unique(org,account,approval_row_id,audit_event_id) bounded FK target. event_kind exact domain vocabulary; actor_kind membership/repricer_worker/backfill; actor_membership_id nullable canonical org FK; before_status nullable/after_status required; before_version nullable/after_version required integral NUMERIC; occurred_at; attempt_id nullable scoped FK; before/after attempt version nullable SMALLINT; reason/error/upload/result nullable typed fields. No raw metadata/body text. Keep all event refs exact and scope-qualified.

Rows immutable by grants+BEFORE UPDATE/DELETE/TRUNCATE denial. Logical unique `(org,account,approval,kind,after_version,attempt_id,after_attempt_version)` must handle null equality. Do **not** blindly B-tree-index an unbounded NUMERIC imported version: use bounded surrogate/UUID event ownership plus account-serialized exact logical comparison/finite witness slots. It preserves domain uniqueness without imposing an unrelated version-size limit. A bounded index `(org,account,approval_row_id,event_kind)` efficiently locates the at-most-finite lifecycle events; NULL semantics use `IS NOT DISTINCT FROM`.

Audit witnesses are a concrete way to enforce that an audit cannot be inserted without a corresponding mutation, or a mutation without its audit, while remaining exactly three relations:

- approval creation/import owns created_audit_id; claim fills claimed_audit_id; pending reject/block fills decision_audit_id; terminal apply result fills outcome_audit_id;
- attempt insert owns reserved_audit_id; marker fills dispatched_audit_id; terminal attempt outcome fills outcome_audit_id **equal to approval.outcome_audit_id**;
- pointers are populated at the same business transition, UUID known to trusted caller before the two inserts/updates. They never change afterward and cannot be patched in by a metadata-only UPDATE; ordinary approval version/time semantics are preserved;
- create/import INSERT has its audit UUID immediately (audit row may be inserted later in the same transaction because FK is DEFERRABLE INITIALLY DEFERRED). Attempt reserve similarly knows both UUIDs before INSERT. No nullable committed half-created root is required;
- deferred audit-insert validator requires that exact audit UUID be referenced by the corresponding durable witness slot, owner scope, event kind and attempt. This rejects an extra “historical” audit row merely matching a still-existing claimant/version;
- deferred mutation validators use captured OLD/NEW transition values, not just the current row, to compare exact event time/status/version/actor/result. They allow later legitimate transitions in the same transaction without interpreting the final row as the original intermediate state;
- witness inverse checks and captured transition checks together prevent forged/no-mutation audit rows, omitted audit and pointer reuse. This does not make a membership ID authentication evidence: actor authorization remains trusted service/shared guard work.

All circular approval/attempt/audit FKs are scoped and deferred; create tables then add cyclic FKs. No FK includes mutable current approval.version. No extra transition-log or outbox table is needed. If implementation elects an alternative equally strong mechanism, it must prove these same no-ghost/no-omitted-audit cases rather than downgrade to receipt-only checks.

## 6. Deferred final lifecycle invariants

Queue one DEFERRABLE INITIALLY DEFERRED constraint-trigger validation for each touched approval/attempt; resolve by bounded surrogate owner key. Read final current row and all owned attempts plus captured mutation events. Queries execute while account lock is still held. Rules:

1. Legacy approval never has an attempt; no legacy lifecycle UPDATE. Imported applying/applied/failed/ambiguous is valid historical state only, with imported audit and exact original actors/code semantics.
2. V1 pending/rejected/blocked has zero attempts. Applying may have **zero attempts** (committed post-claim prefix), or exactly one reserved/dispatched attempt. Do not impose a mandatory attempt on every applying row.
3. For an existing attempt, owner/approval surrogate/action_key/request_checksum/claimant match the immutable approval intent/claim. While applying, approval.version = attempt.claim_version. At v1 terminal applied/failed/ambiguous, approval.version = attempt.claim_version+1. **Never FK frozen claim_version to mutable current approval.version.**
4. V1 applied/failed/ambiguous requires exactly one correspondingly terminal attempt. State, error/upload/result match; approval.updated_at=attempt.finished_at and shared outcome audit. Applied v1 requires result_code despite legacy applied allowing NULL.
5. Immutable claim audit fixes original applying version/claim actor. Reserve/dispatch audit uses that unchanged approval version; attempt state and marker history agree with its stored witnesses. A prefix later finalized never erases claim/reserve/marker evidence.
6. Zero-row CAS or exact create/reserve replay writes nothing, including witness slots/audit/version. Marker replay always conflict, never “idempotent permission”. Terminal replay cannot transition/retry; create replay may read current terminal snapshot after fresh authorization.
7. Deferred validators also run on audit INSERT and relevant root/attempt mutations. Reject duplicate audit or FK mismatch even if current row CHECKs pass. Nonempty evidence cannot disappear through DELETE/TRUNCATE or cascading FK actions.

SQL constraints prove consistency of admitted records. They cannot prove that a provider call occurred after a committed marker, that WB rejected a request, or that an HTTP caller authenticated a membership; those remain separate service/integration tests.

## 7. Collision-safe long identity and account lock protocol

Logical `(org,account,approval_id)` uniqueness is mandatory, but an ordinary B-tree UNIQUE on arbitrary TEXT can fail at PostgreSQL index-entry limits. Chosen physical solution: owner-leading bounded surrogate indexes, full binary TEXT equality and **account-serialized READ COMMITTED checks**. No lookup hash in this initial migration. Exact-key replay checks every immutable field/bytes after fresh authorization. Account-local scan/contention cost is explicit; no throughput claim. A later nonunique digest accelerator would need separate forced-collision proof and cannot replace exact equality.

Require context `(app.organization_id, app.marketplace_account_id)` for every scoped mutation. A VOLATILE BEFORE STATEMENT trigger for INSERT/UPDATE on all three tables locks the exact canonical WB account FOR UPDATE **before tuple mutation locks**, and rejects other transaction isolation levels. A separate subsequent SQL command performs full-text lookup after any lock wait; a DEFERRABLE final uniqueness check repeats exact equality while the account lock remains held. Fresh READ COMMITTED snapshots, not a pre-wait statement/ORM cache, are required. Concurrent same-ID inserts serialize and the loser sees the committed exact row; multi-row duplicates in one transaction are caught by row/deferred checks.

Do not acquire account only in a BEFORE ROW UPDATE trigger: the executor may already own the approval tuple, creating approval→account versus account→approval inversion. BEFORE STATEMENT locking plus repository discipline avoids that ordinary DML inversion. Service still acquires shared user/session/membership authorization locks **before** any account/approval SELECT FOR UPDATE; direct callers must not take domain tuple locks then request auth/account locks. Malicious/incorrect manual lock order may be aborted, never accepted as consistency proof.

Full command lock order: user SHARE → membership SHARE → login session SHARE → account UPDATE → any required exact credential metadata SHARE → approval UPDATE → attempt UPDATE → row mutations/audit. All account IDs sorted if a caller batches administrative work; this initial command targets one account. No network or own-session resolver under these locks. Import/mutation helpers are scoped and use same account serialization. Never use an unqualified hash/advisory lock as an authorization mechanism.

Pending scan index becomes `(org,account,created_at,approval_row_id) WHERE request_format='wb-price-apply/v1' AND status='pending'` rather than the suggested long-text tail. Surrogate is a stable bounded tie breaker; no external ordering contract is changed. Recovery index `(org,account,updated_at,attempt_id) WHERE status='dispatched'`. Exact lookup always retains owner and full approval-ID equality.

## 8. RLS, runtime/default ACL and import

All three tables ENABLE+FORCE RLS. Policy predicate:

```text
organization_id = positive_integer_context('app.organization_id')
AND marketplace_account_id = positive_integer_context('app.marketplace_account_id')
```

Same expression for USING/WITH CHECK. Missing/empty/invalid/out-of-range context returns no authorized rows or a bounded denial, never default org/account. Existing committed `set_tenant_context` sets **only org**; add `set_marketplace_account_context(session, *, organization_id, marketplace_account_id)` to `app.infra.db`, requiring an existing clean active root PostgreSQL transaction and canonical positive INTEGER IDs, SET LOCAL, root-transaction markers and pooled-context cleanup tests. Preserve existing `set_tenant_context` behavior for unchanged consumers; the new helper verifies the org context as well as setting both exact values. It sets context, not permissions. No broader existing Orders/Reviews policy is silently changed.

Runtime role is neither table owner nor superuser/BYPASSRLS, cannot SET ROLE to migration/import owner, alter functions/policies/triggers, change session_replication_role, create in trusted schema, grant itself rights, or receive grant options. Give SELECT/INSERT/UPDATE on approvals and attempts subject to transition triggers; audit SELECT/INSERT only; no DELETE/TRUNCATE/REFERENCES/TRIGGER. Runtime legacy INSERT denied by policy/guard; migration/import role explicitly authorized by DB ownership/role membership and retains audit requirements. Runtime-created backfill actor is rejected. No new identity sequences in this design; do not grant any sequence UPDATE or setval capability for convenience.

Migration-time defense must account for **already inherited broad default ACLs**, before any later runtime-role script. Follow existing T1 migration approach: inspect ACL grantees on the three newly created relations; revoke all non-owner table/column privileges (and grant options), then restore only already granted allowed operations intersected with the table-specific allowlist. For PUBLIC restore nothing. Inspect column ACLs as well as relacl so an inherited/previous column grant cannot retain a forbidden path. No new grantee or unrelated old-object/default-ACL rewrite is authorized by this slice.

Update eventual `backend/ops/runtime-db-role.sql` with these narrow grants/revokes **after** its broad schema/default grants, so rerunning it does not restore DELETE/TRUNCATE/audit UPDATE or import bypass. New functions default PUBLIC EXECUTE must be revoked and selectively allowed; mutating trigger functions must not be callable as arbitrary bypasses. ACL verification uses actual runtime and another inherited-default role. FORCE RLS and scoped FK checks remain independently tested; superuser test connections are not runtime proof.

Safe errors are generic fixed codes. No full row/request/approval text inside RAISE EXCEPTION, JSON errors, task args or generic audit. DB parse errors can reflect values; reject hostile Unicode/UUID/input types in domain before casting and sanitize database exceptions in service.

## 9. Empty-only downgrade

Under authorized owner visibility, acquire ACCESS EXCLUSIVE locks on all three exact tables in a fixed order before counting. Inspect all rows regardless of tenant context; do not rely on an owner SELECT hidden by FORCE RLS. A migration session must have genuine all-row visibility (appropriate privileged migration role); `row_security=off` alone does not grant bypass and must not be presented as one. Refuse downgrade atomically if any table is nonempty.

Only after all-empty proof: drop named cyclic FK/trigger dependencies, then audit/attempt/approval tables and this migration's dedicated helpers in dependency-safe order. No CASCADE; no deletion/archive to make the guard pass; no broad shared helper/default ACL changes. Empty downgrade and upgrade round-trip belong to disposable tests. Failure acquiring locks or proving visibility fails closed.

## Remaining decisions and limits

Local implementation choices are concrete here: UUID surrogates/witnesses, integral finite NUMERIC, exact ASCII SQL reconstruction, account-serialized full-text uniqueness, two-context RLS, statement-level account locking, deferred final lifecycle/audit checks and narrow ACLs. They can be adopted by T1 without another T2 semantic amendment; alternate implementations must prove equivalent invariants. No revision is proposed.

Actual remaining external/domain activation gates: authenticated worker execution source, fresh price:send/service authorization and legacy writer cutover, trusted provider rejection/success evidence mapping, and owner retention/removal policy. They do not block the three-table local DDL. The dedicated account-context helper and runtime/import-role grant selection are shared T1 implementation work, not user business-policy questions.

Critical pass challenged the long-text and huge-NUMERIC B-tree limits, account-lock snapshot timing, row-trigger lock inversion, Unicode serialization parity, a frozen claim-version FK mistake, ghost-audit insertion, role/default-ACL bypass and RLS-hidden downgrade counts. None is treated as already solved/tested by this prose; the proof matrix remains required before acceptance.
