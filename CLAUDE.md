# CLAUDE.md — Проект "SAAS для Огней"

> Читать перед каждой новой сессией по этому проекту.

## Кто клиент

**"Огни"** — производство DTF/DTG-печати на одежде (футболки, худи).
- Продаёт на **Wildberries** (схема FBS, 33 склада, 1 кабинет) и **Авито** (10-15 аккаунтов планируется, 4000₽/мес каждый)
- Артикул = принт × цвет × размер. **~1500 плавающих артикулов**, 10-15 новых/неделю
- Кодирование: L=лонгслив, F=футболка, H=худи; ХБ=белый, ЛЧ=чёрный
- Дедлайн WB FBS: **120 часов**, штраф 50% стоимости товара без верхнего предела
- Сейчас платит ~100K/мес за **INDEEPA** (indeepa.com) — это репрайсер WB/Ozon, **Авито у INDEEPA нет**

## КРИТИЧЕСКОЕ ОТКРЫТИЕ (апрель 2026)

**Клиент называл "Indip" — это INDEEPA** (indeepa.com) — авторизованный WB-партнёр, работает только с WB/Ozon/ЯМ.  
**Авито клиент вёл через AcreOne** (подтверждено на брифинге 15.04.2026).

Полная картина инструментов клиента:
- **INDEEPA** (~100K/мес): WB-репрайсер, ночная медиана, акции, «Рука на пульсе», ABC-анализ → **заменяем M3**
- **AcreOne** (тестировали): Авито мультиаккаунт, чаты, буст, автопополнение кошельков → **заменяем M1**
- **1С** (две системы): управленческая + бухгалтерская → **не интегрируем** (исключено из скоупа, 23.04.2026)
- **1С-Битрикс**: внутренняя коммуникация, задачи, доступы → **остаётся**
- **MPstats**: пробовали как автоответчик отзывов → **отказались** (однотипные ответы)
- **Google Таблицы**: ручные отчёты, ABC, неделя-к-неделе → **заменяем**
- **Merstats**: счётчик остатков WB (дополнительно)

Проблемы: «Рука на пульсе» нечитаема, расчёт поставок неудобен, AcreOne бот 3 мес без результата (баланс 0 ₽ → AI не работал).

## МОДУЛИ

Полный скоуп из утверждённых ТЗ (`ТЗ/TZ-WB.md`, `ТЗ/TZ-Avito.md` v1.0 от 20.04.2026).

### Фаза 1 — WB (замена INDEEPA)

1. **Репрайсер WB** — COGS → P_min/P_max, **корзины как основной сигнал** (не продажи), ночная медиана (23:00–04:00), защита от акций через `min_price`, флаг для ликвидации с отрицательной маржой
2. **Сводные отчёты WB** — 10 типов (Продажи, Заказы, Остатки, Возвраты, P&L, Рентабельность, Реклама, Позиции, Неделя-к-неделе, Сводный дайджест), аналитическая витрина (объединение ~10 отчётов), Telegram-дайджест 08:15, экспорт Excel/PDF
3. **Отчёт по ликвидации** — кандидаты по оборачиваемости/корзинам/рекламе → галочки → подтверждение → плавное снижение цены каждые 24ч
4. **Автоответы на отзывы WB** — 100–150/день, два бренда (зумеры/женщины), ИИ-генерация, маршрутизация по рейтингу

### Фаза 2 — Авито + Заказы (замена AcreOne)

5. **Авито Мультиаккаунт** — единый чат на 10–15 аккаунтов, бот-автоответчик чатов, управление объявлениями через XML-фид (с контролем «все объявления за раз»), генерация фото нейросетью (3 варианта lifestyle), статистика
6. **Репрайсер Авито** — триггер по просмотрам/обращениям, снятие объявления при отсутствии интереса месяц
7. **QR-коды возвратов** — кнопка в карточке заказа, таблица печатника + таблица курьера, массовое оформление
8. **Автопополнение кошельков Авито** — мониторинг баланса раз в 4ч, ЮKassa, дневной лимит
9. **Автоответы на отзывы Авито** — аналогично WB, два бренда

### Сквозное

10. **Заказы WB+Авито и производство** — единая очередь, таймер 120ч, стикеры WB, **КИЗ Честный знак** (пул одноразовых кодов, стоп при пустом пуле), маппинг артикулов, группировка по принту, PDF в 8:00

## ПРОИЗВОДСТВЕННАЯ СПЕЦИФИКА КЛИЕНТА

- Термопресс: 40-120 изделий/час, цикл 30-60 сек
- Полный цикл заказа (пресс + упаковка + стикер): 5-8 мин
- Склад = **бланки** (белые/чёрные футболки по размерам), не готовые SKU
- Оптимизация = **группировка по принту**, не по времени заказа
- PDF с заказами в 8:00 утра (кроме выходных), выходные → понедельник
- 3 основных себестоимости: футболки, худи, лонгсливы
- Возвраты Авито: ручная отдача 100+ товаров, QR-коды для возвратов отличаются от первоначальных

## ПРАВИЛА РАБОТЫ В СЕССИЯХ

1. **ВСЕ поиски → EXA MCP** (`mcp__exa__web_search_exa` или `mcp__exa__get_code_context_exa`)  
   Не использовать WebSearch никогда. Это жёсткое правило.

2. **Язык документов** → русский. Технические исследования допускают английский.

3. **Research файлы** → `research/` в корне проекта. Нумерация продолжается от 22+ (1–21 уже заняты).
   Устаревшие материалы — в `research/archive/` (tz-drafts, kp-drafts, briefing-prep, foreign-clients).

4. **IP-права** → договор о намерениях с явной клаузой об IP **обязателен до начала любых работ**.  
   Ст. 1296 ГК РФ: без контракта исключительные права переходят к клиенту.

5. **Автоакции WB** → не обещать API-управление. Объяснять: единственная защита — `min_price`.

6. **Бюджет** → не поднимать разрыв 600K vs 800K первым. Выяснить контекст, затем фазировать.

7. **Единая дизайн-система → production Vella**. Для всех новых модулей и доработок использовать только актуальную Vella-дизайн-систему из production-репрайсера (`https://ogni-saas.vercel.app/wb/repricer`) и локального канонического файла `frontend/public/vella-production.html`. Не использовать старые prototype/demo HTML, старую светлую отчётную UI-основу "Огни" (`ReportLayout` / `KpiStrip` / card-grid style) или самостоятельные новые shell/layout без отдельного подтверждения. Отчёты должны использовать тот же shell, sidebar, topbar, tabs, KPI, toolbar, table, drawer и CSS tokens/classes из `vella-production.html`; при открытии отчётов группа репрайсера свернута, группа отчётов раскрыта и визуально отделена. Все функциональные элементы отчётов должны иметь короткие tooltip-пояснения.
