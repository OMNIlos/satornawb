## Автоматические проверки

- Frontend: новые XLSX/WB-контракты и ABC-контракт — 9/9 тестов пройдено.
- Backend: календарь/воронка, ABC aggregate cache и XLSX endpoint — 5/5 тестов пройдено.
- TypeScript и production build проходят вместе с уже существующими незакоммиченными изменениями Settings shell основной ветки.
- Два старых source-text теста `weekLiveSource.test.ts` не соответствуют исходной ветке: они запрещают `ReportProgressPanelIsland`, уже присутствующий до этого WB diff.

## Сверка CodeMP

Новая сессия CodeMP 01.10.2026 не была доступна после истечения браузерной сессии. Использована последняя документированная remote-control сверка периода 12–18.09.2026 с предыдущим периодом 05–11.09.2026, которая хранится вне Git из-за финансовых данных клиента.

- Выручка после возвратов, комиссия с эквайрингом, логистика, хранение и приёмка совпали с финансовым снимком Satorna.
- Расход рекламы fullstats и денежные списания CodeMP имеют разные основания учёта; одно значение не подменяется другим.
- Полную чистую прибыль нельзя считать подтверждённой для строк без датированной себестоимости или сверенной классификации операций.

## Производительность и hot points

- Production HTML TTFB в трёх запросах: 0,482 / 0,521 / 0,720 с. Это не подтверждает Vercel как основной источник задержки.
- Основные JS-чанки после сборки: 1 561,30 kB и 2 394,70 kB minified (316,09 и 578,00 kB gzip). Это заметный клиентский hot point; нужен route-level code splitting.
- Отчёты показывают белый экран примерно 2–8 с, пока загружаются API/cache и строится большая таблица. Начальный batch репрайсера уменьшен со 150 до 50 строк.
- Worker-диагностика показала устаревший WB sync и незакрытый этап. Это может давать старые цифры независимо от хостинга frontend.
- Рекламный источник не заполняет часть campaign metadata; фильтры готовы, но их полезность зависит от полноты backend/WB cache.
