# Статистика репрайсера: фильтры, метрики и динамика

Дата: 17.09.2026. База: `codex/products-stock-period-20260917` (`4758f73`).
Продакшен backend на момент проверки: образ `d439228`, предок указанной ветки. Маршрут: `/wb/repricer/stats`, API: `GET /api/v1/wb-repricer/stats`.

## 1. Динамика в заголовках

- Справа от названия каждого **числового показателя за период** показывать `↑` зелёным, если агрегат по видимым товарам больше, и `↓` красным, если меньше, чем в непосредственно предшествующем периоде той же длины. При равенстве, отсутствии или неполноте сравнимых данных стрелки нет; вместо неё доступно объяснение через `title`/подсказку.
- Период включителен по обеим датам. Например, выбор 10–16 сентября сравнивается с 3–9 сентября. Для пресетов применять фактические даты, которые отправлены API, и исключить смещение часовых поясов при вычислении предыдущего интервала.
- Сравнение пересчитывается после смены дат, поиска и любых фильтров. Для каждой колонки брать только видимые SKU с достоверным значением этой метрики в обоих периодах, сопоставленные по `articleId`; неполный источник воронки исключает SKU из сравнения метрик воронки. Новые SKU без предыдущего наблюдения не создают ложного роста. Проценты (CTR, CR, DRR) сравниваются как доли от сумм числителя и знаменателя, цена — как средняя взвешенная по заказам. Не усреднять проценты SKU.
- Стрелки не ставить у идентификатора товара, ответственного, действия, защиты цены, статуса источников и текущего остатка: это не сопоставимые показатели потока за период. Цвет означает направление значения, а не оценку полезности (например, рост DRR тоже зелёный).
- Ошибка загрузки прошлого периода не блокирует текущую таблицу и оставляет стрелки скрытыми. Устаревший ответ от предыдущего выбора дат не должен перерисовать новые данные.

## 2. Фильтры как на «Все товары»

- Над таблицей разместить кнопку `Фильтры N`, краткое описание выбора и панель с тем же расположением, стилем, подписями и действиями `Очистить`/`Применить`, что на вкладке «Все товары» (референс — скриншот пользователя).
- Разделы: системные сегменты (`Все`, `SKU ниже порогов`, `Без P_min`, `Маржа ниже 0`, `Изменения 24ч`, `Неликвид`), ответственный (`Все менеджеры`, `Мои товары`, `Без ответственного`, конкретные менеджеры), состояние товара, акции, бренд, диапазоны маржи/корзин/заказов/цены, тип одежды, пол/цвет, стратегия, бренд, остаток и видимость колонок.
- Все условия применяются именно к статистике; состояние фильтров не меняет «Все товары». Числа у вариантов считаются по полученным строкам статистики выбранного периода. Поиск и условия объединяются через AND; варианты внутри раздела типа/атрибутов — через OR. `Очистить` восстанавливает исходное состояние, `Применить` закрывает панель и обновляет строки, счётчик, KPI и динамику. Пустой результат показывает явное состояние без строк товара.
- Фильтр `Изменения 24ч` опирается только на реальный журнал изменения цены, а не на технический `lastSavedAt` в метаданных товара. Если журнал недоступен, сегмент показывает ошибку источника, не выдуманные совпадения.
- Колонки скрываются вместе с соответствующими ячейками, но выбор колонок не влияет на расчёт метрик.

## 3. Новые и раздельные метрики

| Колонка | Источник и вычисление |
| --- | --- |
| Показы | Общие показы товара из поля `impressions`/`viewCount` в подтверждённом ответе WB за период. Если API не отдаёт поле, `null` → `—`; рекламные показы сюда не подставлять. |
| Показы рекламы | `adImpressions` из рекламной статистики WB. |
| Общие клики | `openCount` воронки WB: все переходы в карточку, включая рекламный трафик; не складывать с рекламными кликами. |
| Клики рекламы | `adClicks` из рекламной статистики WB. |
| Корзины рекламы | `adCartAdds` (`atbs`) из рекламной статистики WB. |
| Корзины | `cartCount` воронки WB. |
| CTR | `adClicks / adImpressions × 100`, если знаменатель больше нуля и оба источника полны. Подпись уточняет, что это **CTR рекламы**. |
| DRR | рекламные расходы / выручка за выбранный период × 100, если знаменатель больше нуля и оба источника полны. Расходы остаются отдельной колонкой. |

- `0` допустим только при подтверждённом доступном источнике; отсутствие источника = `null`/`—`. API сохраняет исходные поля для обратной совместимости, добавляет `totalImpressions`, `totalClicks` и `averagePriceKopecks` с явными именами.
- Сводные KPI и фильтрация должны читать те же значения, что ячейки. Нельзя переносить CTR в ячейку кликов или DRR в ячейку расходов.

## 4. Названия и средняя цена

- `Конверсия` → `CR`; подсказка: `заказы / корзины × 100`.
- `Цена-ориентир` → `Средняя цена за период`; брать фактическую среднюю цену заказа за выбранный период (`orderSumKopecks / orderCount`) из воронки. Не заменять её текущей ценой или медианой. Если заказов или суммы нет, `—`.

## Этап 2: сводка и скорость вкладки

### Вкладка и исходные карточки

- Удалить подпись «черновик» у пункта «Статистика» в боковом меню и верхнем переключателе.
- Исключить все статические демонстрационные значения карточек. Четыре исходные карточки питаются текущим ответом статистики: «Добавили в корзину» = `cartCount` воронки WB; «Готовы к пересчёту» = число решений `can_recalculate` внутренних правил; «Цена заблокирована» = число `priceProtection.status=blocked`; «Источники для пересчёта» = отдельные количества `ready`, `partial`, `blocked` по внутренним проверкам, включая СПП и комиссию. Последняя карточка не описывает доступность метрик воронки WB. Статус «частично» нельзя подписывать как «требует действия», а блокировку цены нельзя объяснять конкретной причиной без подтверждения.
- `null` и ноль различать. Если источник отсутствует, показывать `—`; если часть SKU или дней не покрыта, показывать известную сумму только с подписью о покрытии. Фильтры и поиск пересчитывают карточки по выбранным товарам; без фильтров API возвращает сводку сразу по всему ассортименту, независимо от страницы таблицы.

### Полная сводка по числовым колонкам

Добавить карточку для каждой из 13 числовых колонок: `Показы`, `Показы рекламы`, `Общие клики`, `Клики рекламы`, `Корзины рекламы`, `Корзины`, `CTR`, `CR`, `Заказы`, `Реклама, ₽`, `DRR`, `Остаток`, `Средняя цена за период`. Корзины используют исходную первую карточку, поэтому вместе с тремя служебными карточками на экране 16 карточек.

- Счётчики и суммы (`Показы`, `Показы рекламы`, `Общие клики`, `Клики рекламы`, `Корзины рекламы`, `Корзины`, `Заказы`, `Реклама, ₽`, `Остаток`) складывать по SKU с доступными значениями. Подпись указывает `N из M товаров`; частичное покрытие дат воронки указывать отдельно. Остаток — текущий снимок WB, не поток за выбранный период.
- `CTR` = сумма рекламных кликов / сумма рекламных показов × 100; `CR` = сумма заказов / сумма корзин × 100; `DRR` = сумма расходов на рекламу / сумма выручки × 100. Для каждой дроби брать только SKU, у которых доступны оба её компонента; знаменатель должен быть положительным. Нельзя суммировать или усреднять проценты отдельных SKU.
- `Средняя цена за период` = средневзвешенная по числу заказов из воронки WB: `Σ(средняя цена SKU × число заказов SKU) / Σчисло заказов SKU`. Текущая цена товара не подставляется.
- Рекламные показы и клики не считать нулём из-за одного только доступного расхода из финансового отчёта. Заказы, выручка, остатки и общие клики также показывать как отсутствующие, когда их источник не загружен.
- Показывать время последнего обновления воронки, рекламы, финансов и остатков из метаданных API, чтобы сверка с более свежим кабинетом WB не выглядела как совпадение данных на разных срезах.
- В кабинете WB Seller общие «Показы» видны, но официальный `POST /api/analytics/v3/sales-funnel/products` не содержит их в ответе для подключенного аккаунта. Пока официального поля нет, карточка показывает `—` и причину; рекламные показы не заменяют общие. CTR в этой таблице **рекламный** и потому не равен CTR общей воронки Seller.
