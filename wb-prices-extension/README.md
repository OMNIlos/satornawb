# Satorna — цены Wildberries

Manifest V3 для Chrome / Edge / Яндекс Браузера, без npm-зависимостей. Нужен Chromium 111+ с MAIN-world content scripts. Использует небольшой scaffold и copy-build существующего `avito-orders-extension`; WB-парсер и обмен данными отдельные.

Устанавливается только **собранный `dist` или готовый ZIP**. Сборка объединяет общий contract и observer в один MAIN entry: один и тот же filename в двух static worlds Chrome не обеспечивает доступность contract в обоих мирах. Исходный manifest поэтому ссылается на генерируемый `src/page-observer.js`; build проверяет его наличие.

## Проверка и установка

```sh
npm run check
npm run build
```

Готовый ZIP распакуйте в постоянную папку и выберите её при установке. Не удаляйте эту папку после установки. Расширение не устанавливается автоматически.

- Chrome: `chrome://extensions` → режим разработчика → «Загрузить распакованное расширение» → каталог `dist`.
- Edge: `edge://extensions` → режим разработчика → загрузка распакованного расширения → `dist`.
- Яндекс Браузер: `browser://extensions` → режим разработчика → загрузка распакованного расширения → `dist`.

Совместимость Edge и Яндекс заявлена по используемому Chromium/MV3-контракту; локальная живая проверка в них ещё не проведена.

В Satorna создайте токен **WB-расширения**, вставьте его в popup и нажмите «Проверить подключение». Подключение подтверждается только успешным чтением каталога API. «Начать сбор» открывает собственную неактивную вкладку. «Остановить» сохраняет прогресс и отменяет автоповтор, «Продолжить» заново проверяет каталог. «Забыть ключ» удаляет локальный токен; отзыв серверного токена выполняется в Satorna.

## Что собирается

- Только обычные ответы страницы WB: `cards/v4/detail`, `cards/v4/list`, `sellers/v4/catalog` на `https://www.wildberries.ru/__internal/…` с `curr=rub`.
- `products[].id` → `nmId`; `sizes[].optionId` → **точный** `sizeId`; `sizes[].price.product` → цена покупателя без кошелька, целые копейки.
- `supplierId` — публичный ID для перехода на существующий магазин продавца.
- Цена с кошельком пока `null`: поле `price.wallet=0` не является конечной ценой. Скидка кошелька не угадывается.
- В snapshot попадают только пары `nmId/sizeId` из каталога Satorna. Цена продавца и revision берутся из Satorna, цена покупателя не может быть выше неё. Другой размер не заменяет отсутствующий.

Текущий серверный каталог привязан к одному выбранному WB-кабинету и содержит первую размерную пару товара из существующего seller goods cache. Расширение не заявляет охват всех размеров WB: знаменатель счётчика — именно пары, выданные этим API. Каталог ограничен 100 000 парами; неизвестные и отсутствующие размеры не синтезируются.

Сначала открывается карточка для определения продавца, затем его обычная страница. Используется реально присутствующая кнопка/ссылка следующей страницы либо одна прокрутка вниз после полученной страницы каталога. Если за 25 секунд нового ответа нет, магазин отмечается как просмотренный **частично**, и обход переходит к оставшимся карточкам. Полнота магазина не выводится из достижения footer. Искусственные `seller?page=` URL не создаются.

HTTP 403/429, captcha, неизвестная структура или таймаут карточки останавливают сбор; продолжение только вручную. Прямых запросов к внутренним API WB, обхода блокировок и запросов к WBCON нет. Фоновая вкладка может ограничиваться браузером: это не считается успешным сбором.

После завершения прохода следующий запускается **через 20 минут**, пока работает браузер. Это пауза между проходами, а не гарантия обновления каждого товара за 20 минут: длительность обхода и покрытие зависят от доступных WB страниц. Popup показывает точное время следующего прохода и число размеров со свежими наблюдениями. При сне компьютера alarm может задержаться. Ручная остановка, ограничения WB и ошибки доступа отключают автоматическое продолжение.

## Контракт и границы

Фиксированный API: `https://api.elfprint-system.ru/api/v1/wb/browser-prices`.

- `GET /catalog?page=N&pageSize=100`: все страницы должны иметь один account/revision; reference цены продавца не старше `maxAgeSeconds`, максимум 30 минут.
- Только при серверном `409 WB_BROWSER_GOODS_STALE`: один `POST /catalog/refresh` без body и чтение каталога заново с первой страницы. Клиент допускает до 125 секунд для этого запроса. 429/503 или занятый refresh ставят сбор на паузу; циклических повторов нет. Поддерживаются production `error.code` и `Retry-After`, а также обычный FastAPI `detail`.
- `POST /snapshots`: `{goodsRevision,items}`; не более 100 наблюдений в запросе; `observedAt` — время получения background-процессом, не поле страницы. Наблюдения старше пяти минут не отправляются.
- 409 snapshot: однократное перечитывание каталога и повторная проверка перед одним повтором. 401 удаляет токен и останавливает сбор. Неопределённый результат POST автоматически не повторяется.

Счётчики различают свежие наблюдения, принятые и пропущенные сервером строки. Запланированный следующий проход не означает полного покрытия каталога. Наблюдения старше 30 минут перестают считаться свежими.

Штатная приостановка service worker сохраняет текущий шаг; короткие таймеры восстанавливаются, а `chrome.alarms` даёт долговременное пробуждение. После перезапуска браузера включённый сбор заново читает каталог и создаёт собственную вкладку. Явная пауза сохраняется. Токен и минимальные параметры запуска хранятся в trusted local; каталог, цены и текущая вкладка — только в session.

Chromium может завершить service worker, если ответ `fetch` не пришёл за 30 секунд. Поэтому незавершённый refresh записывается заранее: после восстановления выполняется только чтение каталога, когда 125 секунд с начала запроса уже прошли; POST не повторяется. Если каталог всё ещё устарел, сбор остаётся на паузе. Незавершённый POST наблюдений имеет неизвестный результат и требует ручного продолжения, без автоматической повторной отправки.

Токен хранится только в `chrome.storage.local` с `TRUSTED_CONTEXTS`. Content/MAIN scripts не получают токен; WB cookies, заголовки, сырой JSON и текст страницы не отправляются. CRM fetch использует `credentials: omit` и запрещает redirects. Сообщения страницы считаются недоверенными и проходят повторную проверку background-процессом. Токен не даёт расширению интерфейса изменения цен WB.

## Offline-проверки

`node --test` исполняет реальные parser/observer/background/content/popup scripts в изолированных VM. Chrome storage/tabs и HTTP заменены локальными doubles; внешних запросов нет. Проверяются exact size/units, origin/frame/tab guards, отсутствие пересылки лишних полей, sequential chunks, duplicate observations, partial coverage, 409/401/403/429 и остановка. Живой массовый сбор этим набором не подтверждается.

В рабочем репозитории дополнительный `node scripts/browser-check.mjs` использует уже установленный Playwright из `frontend`: загружает `dist` в отдельный headless Chromium профиль, включает offline mode, заменяет HTTP точными синтетическими fixtures, проверяет реальную цепочку MAIN → isolated → background и сохраняет скриншоты в `output/playwright`. Popup отрисовывается как extension page с локальным bridge к командам worker: headless Playwright не предоставляет native action popup как Page, страница панели допускается и в отдельной вкладке расширения; страницы сайтов не могут управлять сборщиком. Сам sender guard отдельно проверяется VM-тестами. Это проверка расширения в Chromium, не живая проверка WB, Edge или Яндекс Браузера.

Платформенные механизмы: [isolated/MAIN content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts), [storage access levels](https://developer.chrome.com/docs/extensions/reference/api/storage), [service worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle).

Версия 0.1.2: панель работает в отдельной вкладке; автоматическая проверка WB получает 10 секунд на штатное завершение. При сохраняющейся проверке сбор приостанавливается. Магазин прокручивается до последних карточек, а не до футера. Карточка без цены учитывается как обработанная и не останавливает проход. Число обработанных товаров показано отдельно от свежих цен.
