# Satorna — цены Wildberries

## Автоматический проход (0.1.6)

Один запуск: существующие пакеты до 100 товаров, затем обычные страницы магазинов и только оставшиеся карточки в одной вкладке. Свежие подтверждённые наблюдения и найденные магазины повторно используются. Публичный транспорт с 403 не повторяется 30 минут; ограничения/CAPTCHA не обходятся.

Каталог магазина прокручивается штатными элементами WB после ACK предыдущих наблюдений, с паузой 1,5 секунды. Дубли ответа той же страницы не останавливают прокрутку. Магазин открывается видимым: скрытую вкладку WB может перестать подгружать. В таком случае расширение сохраняет прогресс и ждёт возвращения во вкладку, вместо перехода на тысячи одиночных карточек; возврат автоматически продолжает сбор, ручная остановка — нет. Видимая страница получает максимум три дополнительных окна ожидания по 25 секунд; после этого резервный обход честно отмечается как частичный. Повторное самостоятельное чтение внутренних URL WB не используется: живая проверка получила 403 на второй странице. 403/CAPTCHA не обходятся, 429 учитывает Retry-After. Заголовки авторизации/cookies не читаются и не передаются в Satorna. Не создаются отдельные окна или вкладки на каждый товар. Вкладку сборщика и браузер нельзя закрывать.

Временные сетевые ошибки и 429 во время активного прохода повторяются максимум три раза с паузами 60/120/240 секунд (не раньше Retry-After). 403, CAPTCHA, неверный ключ, ручная остановка и исчерпание повторов требуют пользователя. После неопределённого POST старый запрос не повторяется: оставшиеся товары наблюдаются заново, и только новый ACK отмечает сохранение. Прогресс в доверенном хранилище браузера переживает остановку MV3 worker и перезапуск браузера; ключ не входит в checkpoint. Изменение кабинета очищает прогресс, изменение ревизии каталога снимает старые отметки пропущенных карточек.

В локальном режиме: `node scripts/build-local.mjs --update` обновляет только проверенную папку `dist-local`, предварительно сохраняя её копию в `output/artifact-backups`. Затем перезагрузите расширение в Chrome. Production API, permissions и `dist` эта команда не меняет. Локальный сервер должен работать. Неполный проход остаётся явно неполным; нет гарантии времени или полного покрытия WB.

Manifest V3 для Chrome / Edge / Яндекс Браузера, без npm-зависимостей. Нужен Chromium 111+ с MAIN-world content scripts. Использует небольшой scaffold и copy-build существующего `avito-orders-extension`; WB-парсер и обмен данными отдельные.

Устанавливается только **собранный `dist` или готовый ZIP**. Сборка объединяет общий contract и observer в один MAIN entry: один и тот же filename в двух static worlds Chrome не обеспечивает доступность contract в обоих мирах. Исходный manifest поэтому ссылается на генерируемый `src/page-observer.js`; build проверяет его наличие.

## Проверка и установка

```sh
npm run check
npm run build
```

Готовый ZIP распакуйте в постоянную папку и выберите её при установке. Не удаляйте эту папку после установки. Расширение не устанавливается автоматически.

- Chrome: `chrome://extensions` → режим разработчика → «Загрузить распакованное расширение» → каталог `dist`.
- Edge: `edge://extensions` → режим разработчика → загрузка распакованного расширения → `dist`.
- Яндекс Браузер: `browser://extensions` → режим разработчика → загрузка распакованного расширения → `dist`.

Совместимость Edge и Яндекс заявлена по используемому Chromium/MV3-контракту; локальная живая проверка в них ещё не проведена.

В Satorna создайте токен **WB-расширения**, вставьте его в popup и нажмите «Проверить подключение». Подключение подтверждается только успешным чтением каталога API. «Начать сбор» открывает собственную вкладку: магазин становится активным, карточки резерва остаются фоновыми. Каталог прокручивается автоматически. «Показать вкладку WB» выбирает именно её, если адрес не изменился. При ожидании видимости возвращение во вкладку продолжает сбор автоматически; при проверке WB выполните её самостоятельно, затем нажмите «Продолжить». Вход в аккаунт покупателя не нужен. «Остановить» сохраняет прогресс и отменяет автоповтор, «Продолжить» заново проверяет каталог. «Забыть ключ» удаляет локальный токен; отзыв серверного токена выполняется в Satorna.

## Что собирается

- Основной путь — публичная витринная выдача `https://card.wb.ru/cards/v4/detail`: до 100 артикулов в одном запросе, без cookies, для региона Москва (`dest=-1257786`).
- Если пакетная выдача недоступна или вернула не все товары, расширение дочитывает обычные ответы страниц WB: `cards/v4/detail`, `cards/v4/list`, `sellers/v4/catalog` на `https://www.wildberries.ru/__internal/…` с `curr=rub`.
- `products[].id` → `nmId`; `sizes[].optionId` → **точный** `sizeId`; `sizes[].price.product` → цена покупателя без кошелька, целые копейки.
- `supplierId` — публичный ID для перехода на существующий магазин продавца.
- Цена с кошельком читается только из явно подписанной видимой цены «с WB Кошельком» у точного товара. Пока поддерживается каталог для товаров с единственным валидным размером в ответе WB: совпадение обычных цен нескольких размеров не доказывает совпадение кошельковых. Старые зачёркнутые цены и скрытые элементы исключаются; несколько оставшихся сумм, отсутствие подписи или неясный размер дают `null`. Чтение DOM ограничено двумя секундами до публикации наблюдения. Поле `price.wallet` не считается конечной ценой; процент скидки не угадывается. Не гарантируется заполнение кошелька для всех товаров.
- В snapshot попадают только пары `nmId/sizeId` из каталога Satorna. Цена продавца и revision берутся из Satorna, цена покупателя не может быть выше неё. Другой размер не заменяет отсутствующий.

Текущий серверный каталог привязан к одному выбранному WB-кабинету и содержит первую размерную пару товара из существующего seller goods cache. Расширение не заявляет охват всех размеров WB: знаменатель счётчика — именно пары, выданные этим API. Каталог ограничен 100 000 парами; неизвестные и отсутствующие размеры не синтезируются.

В резервном режиме сначала открывается карточка для определения продавца, затем его обычная страница. Используются реальные элементы пагинации и обычная прокрутка с ограниченным ожиданием; затем магазин отмечается как просмотренный **частично** и остаётся обход неразрешённых карточек. Скрытая страница не считается исчерпанным каталогом. Полнота магазина не выводится из достижения footer. Новые адреса страниц магазина `seller?page=` и внутренние запросы пагинации не конструируются.

HTTP 403/429 или ошибка структуры пакетной выдачи переключают сбор на резервный обход страниц. HTTP 403, captcha или неизвестная структура уже в резервной вкладке останавливают сбор; продолжение только вручную. Для 429 действуют ограниченные повторы с учётом Retry-After; исчерпание повторов требует пользователя. Обхода блокировок и запросов к WBCON нет. Фоновая вкладка может ограничиваться браузером: это не считается успешным сбором.

Один запуск выполняет один проход: после завершения автоматического второго круга нет. Прогресс и подтверждённые наблюдения сохраняются. Истечение 30-минутной свежести не возвращает обработанный товар в очередь текущего прохода; оно влияет только на актуальность показываемой цены. Продолжение открытого каталога не перезагружает его с первой страницы. После закрытия вкладки восстановление открывает сохранённый адрес; WB может заново отобразить начало каталога, но подтверждённые товары не становятся необработанными. CAPTCHA и ограничения доступа требуют действий пользователя, без обхода защит.

## Контракт и границы

Адрес сервера задаётся в popup, в поле «Адрес сервера Satorna» (например, `https://satorna.example.org`, без `/api`). По умолчанию выбран текущий сервер `https://api.elfprint-system.ru`; это не ограничение домена. Все CRM-запросы используют выбранный адрес + `/api/v1/wb/browser-prices`. Для нового HTTPS-домена Chrome запросит разрешение только при подключении. Остановите активный сбор перед сменой сервера и вставьте токен, созданный именно на новом сервере. Старый токен не переносится автоматически; прогресс старого сервера сбрасывается. Адрес сохраняется в локальных настройках расширения, токен не показывается в ответах состояния. HTTP loopback разрешён только отдельной LOCAL-сборкой.

- `GET /catalog?page=N&pageSize=100`: все страницы должны иметь один account/revision; reference цены продавца не старше `maxAgeSeconds`, максимум 30 минут.
- Только при серверном `409 WB_BROWSER_GOODS_STALE`: один `POST /catalog/refresh` без body и чтение каталога заново с первой страницы. Клиент допускает до 125 секунд для этого запроса. 429/503 или занятый refresh ставят сбор на паузу; циклических повторов нет. Поддерживаются production `error.code` и `Retry-After`, а также обычный FastAPI `detail`.
- `POST /snapshots`: `{goodsRevision,items}`; не более 100 наблюдений в запросе; `observedAt` — время получения background-процессом, не поле страницы. Наблюдения старше пяти минут не отправляются.
- 409 snapshot: однократное перечитывание каталога и повторная проверка перед одним повтором. 401 удаляет токен и останавливает сбор. Неопределённый результат POST автоматически не повторяется.

Счётчики различают свежие наблюдения, принятые и пропущенные сервером строки. Запланированный следующий проход не означает полного покрытия каталога. Наблюдения старше 30 минут перестают считаться свежими.

Штатная приостановка service worker сохраняет текущий шаг; короткие таймеры восстанавливаются, а `chrome.alarms` даёт долговременное пробуждение. После перезапуска браузера включённый сбор заново читает каталог и создаёт собственную вкладку. Явная пауза сохраняется. Токен и минимальные параметры запуска хранятся в trusted local; каталог, цены и текущая вкладка — только в session.

Chromium может завершить service worker, если ответ `fetch` не пришёл за 30 секунд. Поэтому незавершённый refresh записывается заранее: после восстановления выполняется только чтение каталога, когда 125 секунд с начала запроса уже прошли; POST не повторяется. Если каталог всё ещё устарел, сбор остаётся на паузе. Незавершённый POST наблюдений имеет неизвестный результат и требует ручного продолжения, без автоматической повторной отправки.

Токен хранится только в `chrome.storage.local` с `TRUSTED_CONTEXTS`. Content/MAIN scripts не получают токен; WB cookies, заголовки, сырой JSON и текст страницы не отправляются. Запросы к `card.wb.ru` и CRM используют `credentials: omit` и запрещают redirects. Сообщения страницы считаются недоверенными и проходят повторную проверку background-процессом. Токен не даёт расширению интерфейса изменения цен WB.

## Offline-проверки

`node --test` исполняет реальные parser/observer/background/content/popup scripts в изолированных VM. Chrome storage/tabs и HTTP заменены локальными doubles; внешних запросов нет. Проверяются exact size/units, origin/frame/tab guards, отсутствие пересылки лишних полей, sequential chunks, duplicate observations, partial coverage, 409/401/403/429 и остановка. Живой массовый сбор этим набором не подтверждается.

В рабочем репозитории дополнительный `node scripts/browser-check.mjs` использует уже установленный Playwright из `frontend`: загружает `dist` в отдельный headless Chromium профиль, включает offline mode, заменяет HTTP точными синтетическими fixtures, проверяет реальную цепочку MAIN → isolated → background и сохраняет скриншоты в `output/playwright`. Popup отрисовывается как extension page с локальным bridge к командам worker: headless Playwright не предоставляет native action popup как Page, страница панели допускается и в отдельной вкладке расширения; страницы сайтов не могут управлять сборщиком. Сам sender guard отдельно проверяется VM-тестами. Это проверка расширения в Chromium, не живая проверка WB, Edge или Яндекс Браузера.

Платформенные механизмы: [isolated/MAIN content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts), [storage access levels](https://developer.chrome.com/docs/extensions/reference/api/storage), [service worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle).

Версия 0.1.2: панель работает в отдельной вкладке; автоматическая проверка WB получает 10 секунд на штатное завершение. При сохраняющейся проверке сбор приостанавливается. Магазин прокручивается до последних карточек, а не до футера. Карточка без цены учитывается как обработанная и не останавливает проход. Число обработанных товаров показано отдельно от свежих цен.

Версия 0.1.3: при остановке можно открыть фоновую вкладку сборщика из панели. Кнопка не меняет страницу WB и не продолжает сбор без явного действия пользователя.

Версия 0.1.4: сначала запрашивает цены покупателя пакетами по 100 артикулов через `card.wb.ru`, как актуальные WB-инструменты для селлеров. Открытие карточек и страниц продавца осталось резервным путем для отсутствующих товаров или сетевой блокировки пакетного endpoint.
